methodology

How the Load Is Shaped

ParameterSetting
Sites (edge nodes)One edge per 50,000 wire metrics: 1, 5 and 10 edges for the 50k, 250k and 500k tiers; 20 edges on the opt-in 1M rig. One device BIRTH per edge
Metrics50,000 / 250,000 / 500,000 wire metrics resident in Host state; 1,000,000 opt-in
Update ratesCapacity: a ramp that raises offered load step by step until delivered rate stops tracking offered, so the knee is found rather than asserted. Latency: paced at about 10,000 messages/s so the path is measured unsaturated. Fan-in: 600,000 updates/s offered throughout
Payload1,000 metrics per NDATA in the capacity ramp; 50 metrics per message in the codec test; 1 metric per message in the latency test. Sparkplug B protobuf, alias-only after BIRTH
Projection costReal per-leaf tag-write cost injected at 50 microseconds per leaf so the end-to-end figure includes writing values into tags, not just decoding them
DurationWarm-up phase discarded before every measurement (a cold JIT reads as latency on any code). Steady windows of 5 s per ramp step; 20 s soak for heap; node-churn soak configurable to 30 minutes or more
Quiet boxNothing else running. A concurrent Gradle test JVM halves the 500k tier, which is why every published gate says quiet-box

conformance

Conformance Is the Baseline

Eclipse Sparkplug TCK 3.0.0, ratified binary, 2026-08-15: 182 Edge and 52 Host assertions passed, zero FAIL lines across ten runs. Host MultipleBroker and the BROKER profile were not run, stated on the conformance record with the unedited logs.

Run It Yourself

The suite ships in the product repository. Run it on a quiet box and compare against the tables above.

Load suite4 to 6 minutes
./gradlew :common:loadTest --console=plain
./gradlew :common:loadTest --tests io.sparkbridge.perf.CapacityLoadTest
./gradlew :common:loadTest -PloadHeap=9g -Pcapacity1m --tests io.sparkbridge.perf.CapacityLoadTest
./gradlew :common:gatewayBench -PgatewayBench        # against a live gateway
./gradlew :common:standbyDrill                        # two-JVM takeover
# knobs: -Pshards=N  -Dsparkbridge.host.rebirthCooldownMs  -Dsparkbridge.mqtt.maxReconnectMs
