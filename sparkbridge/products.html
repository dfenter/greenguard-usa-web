For your engineers

Under the Hood

Edge publishes over Sparkplug B. Provider is the broker in between. Host hosts the namespace and the modules. Flow is the optional company-wide backbone.

Edge Node · publisher

Edge

Publishes Ignition tag data as Sparkplug and keeps publishing into a disk buffer when the link drops.

Managed broker and policy layer

Provider

Sparkplug-aware MQTT broker, embedded Moquette or HiveMQ CE companion service. Per-site identities, deny-by-default topic permissions, no client count. $1,995 per gateway, priced separately.

Host Application · consumer

Host

Subscribes to the namespace, learns each node's model from its birth certificate, hosts every module.

Backbone · optional

Flow

Streams every point to the whole company, live, lossless and replayable. Its own license.

edge

Edge

A site publishes once, and every system that wants the data subscribes. GreenGuard USA built Edge for what comes after that: link outages, model changes, tag counts in six figures.

CapabilityDetail
250,000 tag budgetScalar leaves and unfolded UDT members count against one budget. A UDT is admitted whole or skipped whole, never half. Subscriptions install in 10,000-path chunks so a large site does not stall the tag system.
Store and forwardDisk-backed, 50 MB default, batched fsync measured at about 2,697 messages/s durable; per-record fsync available. Buffered values keep their capture timestamps and carry is_historical, so a historian backfills the real curve. Measured lossless: 400,000 of 400,000 replayed in 20.33 s.
Device modelingFolders at a configured depth become Sparkplug Devices with their own DBIRTH and DDEATH, hot-reloaded on rescan without disturbing the session. Write-back is deny-by-default: a DCMD is rejected unless a device/metric pattern opts it in.
Sparse TemplatesDefinitions deduplicated ahead of instances; BIRTH carries the full instance, NDATA only the members that moved, explicit null transitions retained.
Metadata foldingUnits, description and ranges ride the birth certificate as a PropertySet, so roughly a third of points leave the steady-state stream while the model becomes more self-describing, not less.
Up to 8 edge nodesEach with its own transport, subscriptions, buffer and birth sequence state, so one site's problem is not another's.
Primary host lifecycleBirths gated on the host's STATE; a valid host-offline terminates the session and walks to the next server. Verified by the TCK PrimaryHostTest.
host

Host

Fleet scale depends on the Host, so that is where the engineering effort went.

The Host passed all nine profiles of the Eclipse Sparkplug TCK 3.0.0, 346 of 346 assertions. The conformance record has the per-profile results and the unedited logs.

CapabilityDetail
Self-learning tagsThe model arrives in the birth certificate; tags appear as sites come online. Templates expand into member tags and folded metadata projects onto standard engineering properties.
Third-party edgesAliases are optional in Sparkplug, and since 2.3.0 the Host accepts births and data from edges that never assign them. UINT32 is read unsigned from either legal wire field, in metrics, DataSet cells, properties and template parameters alike. Verified live against the Eclipse Tahu reference edge.
500,000 wire metricsResident in under 4 GiB, with per-metric cost measured flat from 250,000 through 1,000,000, with no cliff waiting in production.
Sharded ingestPer-node order preserved while sites decode in parallel, bounded queues, and a control-divert path so a death or a command never queues behind a deep backlog of data.
Shared-subscription scale-outMQTT 5 consumers share one broker stream: about 20x delivered ingest with four consumers against one.
Simultaneous multi-serverA session on every configured server, retained STATE per server stamped with that server's connect time, and commands routed only to where the edge was last heard.
Confirmed write-backA command reports success when the edge reflects the commanded value, not when the broker accepts the publish.
ObservabilityLive dashboard, node inventory, Prometheus metrics that separate wire metrics from projected tags and replay volume from live data, and latency histograms.
provider

Provider

Provider is the policy and routing layer for industrial data. It carries plant data between sites and consumers while enforcing identity, permission and connection boundaries. Sparkplug leaves security to the implementation, and the broker is where your security posture actually gets set.

CapabilityDetail
Two broker shapesEmbedded Moquette on loopback for a single node, nothing to install; or a HiveMQ CE companion for MQTT 5, shared subscriptions and Sparkplug Aware certificates. Neither is licensed by connected-client count.
Per-site identity scopingAn edge credential is bound to one group and node; an unlisted edge user is denied. A scoped credential must present its own deterministic client ID, so one site cannot evict another's session.
No command injectionEdge identities cannot publish NCMD, DCMD or STATE at all. Structurally unavailable, proven live against the deployed ACL.
Application-topic ACLOn the SparkBridge broker, UNS, file-transfer and bridge topics are authorized per identity by prefix and denied by default, so one site's credential cannot forge another site's data. On external HiveMQ the broker extension binds client IDs to identities, judges the Last Will topic at CONNECT, and authorizes PUBLISH and SUBSCRIBE as well, deferring rather than allowing where it has no opinion so file RBAC keeps the final authority, and the migration preflight writes those permission blocks for you.
TLS and mTLSHostname verification mandatory; disabling it requires an explicit development-only flag with no production use.
Read-only posture pageThe effective security settings are shown in the gateway UI and cannot be widened from the web.

The Edge talks to any conformant host, and the Host consumes any conformant edge. Start with one module and add the others when it suits you. Full protocol detail is on the resources page.

flow

Flow

A tag-counted system stops scaling at hundreds of thousands of points. SparkFlow keeps a live, quality-stamped value for every point Host decodes, with no tag behind it, and any system in the company can read the stream.

CapabilityDetail
NATS/JetStream backboneHost publishes every decoded point onto a JetStream stream as a named, timestamped, quality-stamped message. Dashboards, historians, analysts and AI pipelines subscribe; the plant is asked for nothing.
No tag behind a pointScreens keep the tags operators watch. Every other point stays instantly available from the stream, so millions of points stop being a licensing or server-sizing problem.
Exactly onceEach message carries a deterministic id, so a retry after a bad link deduplicates instead of doubling. Verified on a live gateway wire capture.
Last-value cacheA key-value store holds the current value and quality of every point. A new dashboard opens with the last known value of everything the moment it loads.
ReplayThe stream keeps history. An analyst can replay yesterday's upset minute by minute from the same subjects the live data uses.
Outage-provenA 60-second link cut on a leaf node buffered 447 readings and reconciled 447 on the hub: zero missing, zero ordering violations.
LicensingRuns on the Host gateway, on its own perpetual per-gateway license. Detail on the SparkFlow page and the pricing page.
How it works together

One reading, all the way through

A pump changes pressure at 9:14 in the morning. Here is that single reading crossing six products, and the one thing about it that never changes.

Your equipmentThe pump Pressure changes on the floor. The equipment records the moment it happened. 09:14:02.117recorded
DriversDirect connect Read straight from the rack, no translator box in between to re-time it or lose it. 09:14:02.117unchanged
SparkBridgeMoves it Sent because it changed, not because a timer fired. The link then drops for four hours, and the reading waits safely. 09:14:02.117unchanged
SparkVaultKeeps it Stored when the link returns, filed under when it happened rather than when it arrived. Your trend shows the real curve. 09:14:02.117unchanged
SparkInjectDelivers it Landed in Snowflake exactly once, so your analysts are not reconciling duplicates by hand. 09:14:02.117unchanged
SparkCalcUses it Feeds the efficiency figure your team reports on, and is marked uncertain if any input behind it went stale. 09:14:02.117unchanged
PassageShares it Read by the historian and SCADA you already own, with no integration project to pay for. 09:14:02.117unchanged

Seven steps, four hours of downtime, one timestamp that never moved. That is what makes the number defensible when a customer, an auditor or your own board asks where it came from. Meanwhile Sentinel proves only the right people could see it, SparkID controls who those people are, and FleetOps shows every site that carried it was healthy.

Why one line

Built to work together

Each product is bought separately, so you only pay for what you need. What makes them a line is that they share the same foundations and the same three commitments.

You will end up depending on this data for reporting, for customer commitments, and sometimes for a regulator. These three commitments are what make that safe, and they hold in every product on this page.

Three commitments
Real time keptEvery reading keeps the time your equipment gave it, so a trend or an incident review reflects what actually happened on the floor.
Outages survivedWhen a link drops, data is held safely and delivered in order once it returns. A bad afternoon does not become a permanent hole.
Locked down firstNothing gets access it was not explicitly granted, including our own software. Security is the default, not a later hardening exercise.

Want to see these drawn as a real estate? The architecture page walks through one PLC, one plant, a rack of backends, and a 200-plant estate, module by module.

Where To Start

Most plants begin by getting their data moving reliably, then keep its history, then open it to the systems and people who need it. You are not buying a platform up front.

Most plants start with Edge and Host on their own and add a module when the need shows up on a gateway they already own, so nothing has to be decided today that can be decided later. See the pricing page for what each module costs.

Not sure which gateway role you have? Pick by what you run today on the architecture page. If you only need to read older or utility equipment into Ignition, the protocol drivers are their own license and do not require SparkBridge.
