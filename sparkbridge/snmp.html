SparkSNMP

SNMP: every switch, UPS and server in Ignition, without a MIB in sight

The network side of a plant is full of equipment that already answers SNMP. Getting it into Ignition has meant a third party driver that wants a MIB file for every device and polls at one rate for all of them.

Browsed 10 MIB-2 groups and 114 variables from a live agent with no MIB loaded, then read them over OPC UA. Same module verified on an 8.3.8 gateway. Full transcripts in the repository as LIVEPROOF.md and LIVEPROOF-83.md.

Point it at the device. The browse tree appears.

SparkSNMP walks the device on connect and builds the Ignition browse tree from what the device actually reports: system, interfaces, IP, host resources, storage, and every table it finds, with the standard names already filled in. There is nothing to import before the first tag is dragged in. Vendor MIBs can be added later for the private branches, but nobody waits on them.

Polling follows the tags. A tag group at one second gets one second; a tag group at a minute gets a minute; bulk requests are packed per device so a 48 port switch is a handful of packets, not a hundred. Traps arrive as tags under the device, with a script hook if you want to act on them.

Writes are supported where the device allows them, and a diagnostics folder on every device tells you whether it is reachable, how many requests went out, and whether you have asked for more than the link can carry.

0MIB files needed for the first 114 tags

The standard MIB-2 tree is compiled into the driver, so a device's system, interface, IP and host resource branches are named correctly the moment it connects. Tables are walked live, so a switch shows exactly the ports it has.

The release gate ran nine load scenarios plus a ten minute soak, including unreachable devices, slow devices, oversubscribed poll rates and trap floods, and every one passed before the module was signed.

Four Situations This Solves

All four are the network side of the plant being treated as somebody else's problem.

The situationWhat changes
The switch died and the first sign was the line stopping
Any plant where the PLC network runs on managed switches nobody monitors.		 Every managed switch reports port status, errors, temperature and uptime over SNMP already. SparkSNMP puts those in the same tag tree as the process, so the alarm fires on the port error count climbing, not on production stopping twenty minutes later. No MIB is needed for the interface table; it is browsed live.
A MIB file for every device before a single tag exists
The integrator who has spent a morning hunting a vendor download page.		 The driver browses the device first and names what it finds from the built in MIB-2 table. Vendor MIBs are optional and can be added to the gateway later for the private branches; the standard branches never wait on them.
One poll rate for the whole device
The engineer who wants port errors every second and serial numbers once a day.		 Polling is driven by the tag groups that subscribe, not a device wide setting that overrides them. Requests are packed per device, so fast and slow tags coexist without hammering the link. A diagnostics tag says when you have asked for more than the device can serve.
Traps go to a syslog box nobody reads
Whoever finds out about the UPS on battery from the shutdown.		 Traps land as tags under the device the moment they arrive, so a linkDown or a UPS on battery is an Ignition alarm like any other, with the varbinds as members. A script hook runs on each trap if you want to route it further.

If you have network gear, power equipment or servers you would rather see next to the process than in a separate tool, this is worth a conversation. Early sites shape the roadmap.
