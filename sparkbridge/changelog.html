Changelog

Version history

Every release, what changed, and what the change was for. Current release: 2.8.0. SparkNotify 0.2.0. SparkRecord 0.1.0. Full customer notes ship in the release package.

  • SparkRecord 0.1.0
    2026‑09‑05

    SparkRecord: tamper-evident record and replay, early access

    SparkRecord 0.1.0 ships the Sparkplug B, MQTT JSON and NATS JetStream (SparkFlow) record sources and the PostgreSQL, TimescaleDB, SQL Server, object store (S3 and MinIO) and Snowflake sinks, behind a writer that conserves accepted records across backpressure, sink failure and shutdown, with every record SHA-256 hashed and chained per stream so a gap or an edit is detectable rather than silent.

    Known limitations in this early access release: Parquet output is deferred to 0.2 (JSONL only), the Snowflake sink is unit-tested but not verified against a live account, production MQTT still auto-acknowledges behind an opt-in manual-ack seam, two residual writer paths can lose a record only if the JVM cannot allocate memory mid-bookkeeping, and neither the side tables nor the record identifier scheme carry a migration path yet.

  • Host
    2026‑09‑04

    GitOps: bundle as source of truth, drift, canary apply, rollback, audit

    Built in a first form and proven on the reference gateway; ships in the next Host release. A bundle is a directory with bundle.properties and one site document per gateway; every document goes through the same checker as the single-site publisher before anything is signed. The Host reports drift on /gitops between the bundle and the configuration version each site declares on its BIRTH, exposes sparkbridge_gitops_drift, applies to one site or all over POST /gitops/apply behind an approvals gate, treats an older bundle as a rollback at a newer sequence, and writes every attempt to an audit file served at /gitops/audit. The SparkGitOps build command renders and signs a bundle from the shell.

  • Host
    2026‑09‑04

    Data contracts: namespace registry, BIRTH validation, violation status tag

    Built and proven on the reference gateway; ships in the next Host release. Register a prefix with an owner, the metadata every metric must carry, and a mode (strict, additive, open) over POST /contracts. The Host adopts each covered node's and device's metric set from its first BIRTH as version 1 and checks every later BIRTH against it: removals, type changes, suspected renames and missing metadata write the reason to _contract/violation beside the node's tags, count on sparkbridge_contract_violations_total, and show on /contracts/page. Additive mode accepts additions and bumps _contract/version.

  • Host
    2026‑09‑04

    Data lineage: wire-boundary hop, source versus arrival time, consumer hops, durable trace ring, lineage page

    Built and proven on the reference gateway; ships in the next Host release. The single-metric trace now starts in the MQTT client callback (WIRE_RECEIPT), records the source timestamp and the store-and-forward replay flag apart from arrival time, and accepts consumer hops (ACCEPTED, QUEUED, PERSISTED, LANDED, RETRIED, REJECTED) over POST /trace/:id/hops. The newest 1,000 completed traces persist in data/sparkbridge-traces.jsonl and survive a restart; GET /trace lists them. GET /lineage?metric= renders the timeline with explicit "not measured" rows for edge and broker boundaries. Reference gateway figures: wire to tag write in 942 microseconds, source to receipt 6 ms.

  • Host, Provider, Broker
    2026‑09‑04

    Zero-touch enrollment: the Host now answers the code

    Built and proven on the reference gateway; ships in the next release. Until now the enrollment library had no central side running in any module, and a bootstrap session could not connect to the hardened broker at all. The Host now starts an enrollment central when the fleet signing key is present, keeps a site registry, issues each site's broker identity inside the signed configuration document, and writes sparkbridge-identities.properties for the Provider and the HiveMQ extension to read. New routes: POST /enrollment/issue (admin) and GET /enrollment (read). Enrollment sessions (sparkbridge-enrollment-*) are confined to the request topic and their own response topic on both brokers; the file-RBAC template grants those two topics to the bootstrap identity.

  • Host, Edge
    2026‑09‑04

    Capacity intelligence: per-site buffer health, seven-day ingest trend, one expansion recommendation

    Built and proven on the reference gateway; ships in the next Host and Edge release. Each edge now declares its store-and-forward capacity and outage coverage on its BIRTH and refreshes the figures every five minutes as ordinary NDATA. The host subtracts time down while a site is away, shows a Buffer column on /fleet, and adds sites[], recommendation{} and history{} to /capacity, with the full ring at /capacity/history (2,016 five-minute rows, persisted across restarts). The recommendation is one of GROW_EDGE_BUFFER, ADD_HOST_MEMORY, ADD_PROJECTOR_SHARDS, ADD_HOST_CONSUMER or NONE, with the sentence to act on and the benchmark row it rests on. Thresholds are settings (sparkbridge.host.capacity.*). The Perspective Overview gains a Capacity tile. See the roadmap.

  • Licensing
    2026‑08‑29

    Edge and Central standalone; one central package

    SparkBridge Edge and SparkBridge Host each stand on their own; SparkLink stays included with Edge. Every Host module is now its own line. SparkFlow, SparkSNMP and the protocol drivers are each licensed on their own, separate from the package. A site gateway needs only SparkBridge Edge.   • SparkNotify 0.2.0
    2026‑09‑04

    SparkNotify: Discord and PagerDuty are finished channels

    SparkNotify 0.2.0 completes the Discord and PagerDuty channels. This release updates SparkNotify only; every other Spark product stays at its own version and does not need reinstalling. SparkNotify now versions independently of the SparkBridge fleet, so it moves off the 2.7.0 fleet bundle onto its own release.

    Discord. Rich embeds are on by default, with per-request username, avatar and thread overrides so one webhook can post under different identities or into a specific thread. Role mentions are explicit and fire only on High and Critical, so a routine alarm never pages a whole role. Discord rate limits are honoured on 429 with bounded attempts, cleared alarms post a follow-up notice once, and webhook URLs plus thread and role snowflakes are validated strictly at configuration time.

    PagerDuty. A full Events API v2 payload with dedup key, severity, source, component, group, class and custom details. US and EU regions, a minimum-priority filter, a configurable severity map, acknowledgement sync that mirrors an Ignition ack as a PagerDuty acknowledge, and resolve on clear. A failed trigger retains its UNRESOLVED state so it stays retryable, and trigger, acknowledge and resolve are applied in order per dedup key.

    Platform. All channel network calls run off the alarm scheduler thread, so a slow or hanging endpoint cannot stall alarm evaluation. Destination hosts are validated before every connect, refusing private, loopback, link-local, cloud-metadata and CGNAT targets by default.

    Version note. The 8.1 line briefly carried 0.1.2, an 8.1-only hot-upgrade fix build that never shipped on 8.3. 0.2.0 re-aligns both lines on one version and includes that fix.

    Email is deprecated. The Email (SMTP) channel is deprecated and scheduled for removal, because Ignition ships its own email notification module. The channel still works in 0.2.0. New deployments should use Ignition's built-in email notification profile, and existing Email profiles should be migrated before the removal release.

    Two known limitations carry into this release: an oversized numeric PagerDuty Retry-After retries with no delay rather than clamping, bounded by the attempt cap; and profile-level Discord clear idempotency has no regression test, a coverage gap rather than a known defect. DNS rebinding defence remains deferred.

    0.2.0 ships for both Ignition 8.1 and Ignition 8.3. Both bundles are on the download page and at the sparknotify-v0.2.0 GitHub release. The 8.3 line has no gateway on this network and ships on green suites plus packaged-module verification, as every prior 8.3 release has.

  • 2.8.0
    2026‑09‑04

    Capacity, enrollment, lineage, contracts and GitOps land on Host

    2.8.0 updates the SparkBridge core modules only: Edge, Host, Provider and the authorization extension for external HiveMQ. Every other Spark product stays at 2.7.0 and does not need reinstalling. Upgrading from 2.7.0 is a drop-in module upgrade in the usual order, Provider then Host then Edge, with no BIRTH-shape break, topic rename or broker-ACL change, and keys issued for 2.5.0 through 2.7.0 stay valid.

    Capacity intelligence. /capacity reports measured headroom and names the next expansion step, and /capacity/history returns the retained trend. BIRTH grows by two Node Info/* metrics carrying each edge's buffer and retention state; as in 2.4.0, a fleet sized close to its BIRTH byte cap should confirm headroom before upgrading.

    Zero-touch enrollment. A one-time code issued at /enrollment/issue lets a new site bootstrap its identity over a signed channel. A site becomes enrolled only once the response is durable, so a failed publish leaves the code redeemable. The file-RBAC role block in the shipped credentials template carries the two enrollment topics; it ships commented out, so uncomment it and adapt the identity. file-RBAC denies silently, and an edge missing those grants simply fails to enroll.

    Lineage, contracts and GitOps. /trace/:id/hops and /lineage expose the per-hop path of a sampled message over a durable ring that survives a restart. /contracts holds each prefix to the shape adopted from its first BIRTH and raises an alarm-able status tag on a violation. /gitops reconciles the gateway against a checked-out configuration bundle, with an approvals gate and an append-only audit trail; apply always publishes the configured bundle and refuses a directory override.

    Redeploy the HiveMQ extension if you run an external broker: upgrading only the module files leaves a stale extension behind. The extension list must report 2.8.0.

    2.8.0 ships for both Ignition 8.1 and Ignition 8.3. Both bundles are on the download page and at the v2.8.0 GitHub release.

  • 2.7.0
    2026‑09‑02

    Licensing: every paid module runs on Ignition's two-hour trial until a key names it

    2.7.0 is a licensing release, and it changes behavior for unlicensed gateways. Every paid Spark module now ships as a non-free module, so the gateway runs it on Ignition's standard two-hour module trial and Reset Trial on the gateway home page restarts the clock. When the trial expires and no verified key in data/sparkbridge-license.key names the product, the module pauses its data path and keeps its configuration and buffers: Edge publishes NDEATH and stops publishing while store-and-forward keeps capturing, Central publishes a retained OFFLINE state and closes its sessions, Provider refuses new broker connections, SparkFlow stops its dispatcher, historians stop ingest but keep serving queries, and drivers disconnect and mark tags out of service. A key dropped in after expiry lifts the pause within about thirty seconds with no restart; removing it re-pauses in the same window. Keys are bound to the gateway system name; keys issued through the shop work on any gateway. Keys issued for 2.5.0 and 2.6.0 stay valid unchanged. SparkLink, SparkCalc and SparkID stay free and are never paused. No BIRTH, topic, broker-ACL or configuration changes. An unlicensed production gateway that upgrades will pause two hours after the modules start: install the key before upgrading.

    Bundles for Ignition 8.1 and 8.3 are on the download page and at the v2.7.0 GitHub release.

  • 2.6.0
    2026‑09‑01

    Hardening and capacity: tiered route authorization, soft licensing, measured capacity, zero-touch enrollment

    2.6.0 is a hardening and capacity release. Status routes now sit behind a tiered authorization policy with READ, WRITE and ADMIN token tiers, and loopback trust is opt-in rather than assumed. The Host gains a /capacity route that reports a measured ceiling from the benchmark evidence and follows the runtime projector-shard count instead of a fixed number. An Edge can now bootstrap its own identity over a signed, TLS-required config channel with an enrollment code, so a new site gateway needs no hand-provisioned credentials file; credentials it writes are owner-only from the moment they exist. Soft licensing is wired into Edge, Host, Provider and Flow through one signed key file per gateway, with entitlements for the wider Spark lineup. A review-fix lane closed several correctness gaps in shared code: bounded reads and a session-cardinality cap, a negative-alias BIRTH crash, a config envelope size cap, correct UINT32 PropertySet decode, a UNS teardown accounting race and a JSON-body read deadline. No BIRTH, topic or broker-ACL changes; from 2.5.0 this is a drop-in module upgrade.

    Bundles for Ignition 8.1 and 8.3 are on the download page and at the v2.6.0 GitHub release. Fleet Ops 0.2.0 ships alongside as its own signed module release.

  • 2.5.0
    2026‑08‑23

    The backbone: SparkFlow ships

    A fourth module, SparkBridge Flow, carries everything the Host decodes onto NATS/JetStream as a unified namespace: one subject per metric with a mandatory device slot and reversible escaping, a body that keeps quality, source timestamp and the historical flag, last-known value and lifecycle in a KV bucket, a digital-twin bucket, and a confirmed-write command path back to the edge with optional Ed25519-signed commands on top of the broker ACL. Every message carries an exactly-once identity minted per BIRTH rather than the mod-256 wire sequence. A Perspective dispatcher feeds views from the stream, a TAGFEED subset projects onto a tag provider and hot-reloads from KV, and leaf-node store-and-forward survived a real 60-second partition with zero acked loss. We ran three adversarial review rounds and a security red team before the freeze. The Host now recognises and clears its own stale retained STATE after an unclean restart instead of demoting itself in a phantom split brain, and the release bundle is version-guarded so the documents in it can't be a release behind the modules beside them.

    Bundles for Ignition 8.1 and 8.3 are on the download page and at the v2.5.0 GitHub release.

  • 2.4.0
    2026‑08‑15

    Standby, fleet configuration and speed

    The availability release. A warm-standby Host takes over by rank when the primary goes away, measured at 244 ms across 25 nodes with zero rebirths and verified live in a two-JVM drill on the release bench. Configuration now reaches each site as a P-256 signed document, with a fleet dashboard, a JSON feed and birth metrics showing what every node is running. The broker extension now authorizes PUBLISH and SUBSCRIBE, deferring rather than allowing so file RBAC keeps authority. The Ignition trial is enforced across all three modules: they pause on expiry with store-and-forward still capturing and resume on Reset Trial with no restart. The async transport window is on by default, worth 7.3x on replay over a 15 ms link, and the Host adopts parallel decode for 2.7x to 3.9x at 1 to 4 KiB payloads. Also new: per-node SLO statistics, a five-hop trace sampler that costs nothing while disarmed, a generated 180-property config reference, and an importable Perspective status project.

  • 2.3.0
    2026‑08‑15

    Third-party edges welcome

    The interoperability release. We ran the Eclipse reference implementation against the suite and fixed what it found. The Host now accepts edges that never assign metric aliases, which the specification permits and the previous Host refused, and reads UINT32 values from either legal wire field in metrics, dataset cells, properties and template parameters alike. Application-topic authorization now denies by default, version 1 client IDs are no longer accepted, and the HiveMQ authorization extension ships in the release package as an installable artifact. The Host MessageOrdering conformance profile, previously pass-but-incomplete because the reference edge could not birth, now passes every assertion. 531 automated tests.
