Changelog

Version history

Every release, what changed, and what the change was for. The current release is 2.5.0; the full customer notes ship in the release package.

  • Licensing
    2026‑08‑27

    Four modules become features of SparkBridge

    SparkLink, SparkCalc, Passage and SparkID are now included free with any SparkBridge Edge or Central license. Nothing changes in the software; they were built as free modules and stay that way. The site package is now $1,295 (Edge plus SparkVault) and the central server suite $2,995 (Central plus SparkVault, SparkInject and FleetOps). Existing quotes are honoured at the lower of the two prices. See pricing.

  • 2.5.0
    2026‑08‑23

    The backbone: SparkFlow ships

    A fourth module, SparkBridge Flow, carries everything the Host decodes onto NATS/JetStream as a unified namespace: one subject per metric with a mandatory device slot and reversible escaping, a body that keeps quality, source timestamp and the historical flag, last-known value and lifecycle in a KV bucket, a digital-twin bucket, and a confirmed-write command path back to the edge with optional Ed25519-signed commands on top of the broker ACL. Every message carries an exactly-once identity minted per BIRTH rather than the mod-256 wire sequence. A Perspective dispatcher feeds views from the stream, a TAGFEED subset projects onto a tag provider and hot-reloads from KV, and leaf-node store-and-forward survived a real 60-second partition with zero acked loss. Three adversarial review rounds and a security red team ran before the freeze. The Host now recognises and clears its own stale retained STATE after an unclean restart instead of demoting itself in a phantom split brain, and the release bundle is version-guarded so the documents in it cannot be a release behind the modules beside them.

    Bundles for Ignition 8.1 and 8.3 are on the download page and at the v2.5.0 GitHub release.

  • 2.4.0
    2026‑08‑15

    Standby, fleet configuration and speed

    The availability release. A warm-standby Host takes over by rank when the primary goes away, measured at 244 ms across 25 nodes with zero rebirths and verified live in a two-JVM drill on the release bench, and configuration reaches each site as a P-256 signed document, with a fleet dashboard, a JSON feed and birth metrics showing what every node is running. The broker extension now authorizes PUBLISH and SUBSCRIBE, deferring rather than allowing so file RBAC keeps authority, and the Ignition trial is enforced across all three modules: they pause on expiry with store-and-forward still capturing and resume on Reset Trial with no restart. The async transport window is on by default, worth 7.3x on replay over a 15 ms link, and the Host adopts parallel decode for 2.7x to 3.9x at 1 to 4 KiB payloads. Per-node SLO statistics, a five-hop trace sampler that costs nothing while disarmed, a generated 180-property config reference, and an importable Perspective status project.

  • 2.3.0
    2026‑08‑15

    Third-party edges welcome

    The interoperability release, driven by running the Eclipse reference implementation against the suite. The Host now accepts edges that never assign metric aliases, which the specification permits and the previous Host refused, and reads UINT32 values from either legal wire field in metrics, dataset cells, properties and template parameters alike. Application-topic authorization now denies by default, version 1 client IDs are no longer accepted, and the HiveMQ authorization extension ships in the release package as an installable artifact. The Host MessageOrdering conformance profile, previously pass-but-incomplete because the reference edge could not birth, now passes every assertion. 531 automated tests.

  • 2.2.2
    2026‑08‑14

    The conformance record

    All nine profiles of the official Eclipse Sparkplug TCK 3.0.0, run against the ratified binary in one session: 346 assertions executed, 346 passed, zero failed. The published record lives at the TCK results page. Pointing the TCK's reference edge at the Host also surfaced and fixed two interoperability defects: a graceful MQTT 5 disconnect discarded the session's own death certificate, and the Host refused the INT64 form of the bdSeq metric that the reference implementation sends.

  • 2.2.1
    2026‑08‑14

    The hardening pass

    A full adversarial audit of the suite, with every confirmed finding fixed and re-verified: log flood control on every per-message path, replay correctness under reordered session state, fail-closed handling of ambiguous client identities, and the installation guide rewritten against a live gateway rather than from memory. 504 automated tests.

  • 2.2.0
    2026‑08‑14

    The migration window opens

    The staged breaking change. Application-topic use without a grant is reported and counted rather than refused, version 2 client IDs are issued while both derivations are accepted, and a migration preflight sizes the work for an estate and emits ready-made broker permission blocks. Everything this release warned about, 2.3.0 enforces.

  • 2.1.0
    2026‑07‑30

    Scale-out and MQTT 5

    Full MQTT 5 client mode and shared-subscription host scale-out, measured at roughly twenty times the ingest of a single consumer. HiveMQ CE becomes the recommended production broker topology, with the embedded broker remaining the zero-configuration default, and the broker-side authorization extension binds each credential to its derived client identity.

  • 2.0.0
    2026‑07‑17

    Production hardening

    The pass that turned a working suite into a deployable one: bounded decoding on every input path, tiered fail-closed REST authentication, TLS with mandatory hostname verification, secrets moved out of JVM arguments, disk-backed store-and-forward with historical replay, device modeling, and persistent birth sequence numbers that survive gateway restarts.

  • 1.0.0
    2026‑07‑05

    First light

    The first working suite: three Ignition modules speaking Sparkplug B end to end on a live gateway. Edge publishing with report-by-exception, a Host building a managed tag provider from birth certificates, and an embedded broker so a first install needs nothing else.
