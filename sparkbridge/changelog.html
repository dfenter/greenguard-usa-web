  • 3.0.3
    2026‑09‑18

    Enrollment accuracy, pin-preserving reissue, and edge-scope precedence

    3.0.3 is a corrective release on 3.0.2. A site that cannot connect is no longer reported as ENROLLED (#45). Enrollment state was inferred in a way that let a site which had only been issued credentials, and had never confirmed them, appear fully enrolled; such a site now reports CREDENTIALS_ISSUED_UNCONFIRMED until it actually confirms. Reissue preserves the certificate pin by default (#46). Reissuing a site's credentials no longer clears its pinned certificate as a side effect. Clearing the pin is now an explicit opt-in, so a routine credential rotation cannot silently unpin a site. The registry and the identities artifact stay coherent (#47). The site registry and the enrollment identities artifact are written by one path, inside the same operation and under the same lock, so a change reaches both or neither and the two cannot drift apart. An operator's pinned edge scope is no longer silently overridden. An explicit sparkbridge.broker.edgescopes entry is documented to win over the enrollment artifact's entry for the same user, but the artifact was parsed last and quietly overwrote it. Precedence now holds everywhere it is evaluated: at startup, on every hot reload, and on both the embedded broker and the HiveMQ broker extension. A failed pending-serial expiry no longer half-applies. When persisting an expiry fails, the in-memory clear is rolled back, so a restart cannot resurrect a state that was never written to disk.

    Upgrade path. Install the 3.0.3 modules alongside your existing ones, confirm each reaches Running, then uninstall the old ones. Module ids are unchanged, so this upgrade uses the same ids in place, and an existing key keeps working without reissue.

    Bundles for Ignition 8.1 and 8.3 are on the download page and at the v3.0.3 GitHub release.

  • 3.0.2
    2026‑09‑12

    Certificate renewal, reconnect and enrollment fixes

    3.0.2 is a corrective release on 3.0.1. Enrolled edge connects with its issued credential (#36). A zero-touch gateway could finish enrollment and then loop on Not authorized, because the issued broker password never replaced the bootstrap password in the secrets file. Enrollment now writes the issued password into the secrets file as it applies the configuration, before anything tries to connect on the new identity. Certificate renewal survives clock skew (#37). A small clock difference between host and edge could make a freshly issued certificate look not yet valid, so the edge discarded it and the host abandoned the renewal. All three issue paths now backdate notBefore by a five-minute allowance, and a chain refused only for that reason is re-checked on a bounded ladder instead of discarded. Certificate renewal completes reliably (#41, #44). The renewal continuation, including the secrets read for its proof connection, ran on the MQTT client library's own delivery thread, which the library interrupts during connect and disconnect; an interrupted read closed its own channel and failed, and the keystore rollback meant to make that safe failed the same way. Renewal delivery now runs on SparkBridge's own renewal executor, off that thread. A secrets read that is interrupted anyway is retried once on a fresh handle. Secrets reads tolerate interrupts, and report why they fail (#41, #44). Reads and writes now share a lock with a ten-second bound, and a failed read names its cause, error and path instead of one generic message. Reconnect presents a fresh Will with the advanced bdSeq (#33). Reconnect is no longer left to the MQTT client library, which replayed the original death certificate's bdSeq against a new announcement; SparkBridge now performs the reconnect itself so the death certificate and the announcement agree, and a bounce produces one announcement, not two. Broker role carries the UNS publish grant (#43). An enrolled site with UNS mirroring, the default, was disconnected and reconnected roughly every five seconds because its role lacked publish access to its own assigned subtree; the grant is now issued with the rest of the site's permissions. Module shutdown budget. Closing an MQTT connection no longer pays a fixed ~7 second cost when there is nothing left to close (#8). A failed renewal can no longer take down MQTT delivery (#42). Every point where a renewal cycle can be entered from a connection callback now contains its own failures and settles the cycle cleanly. Static bootstrap identity survives regeneration (#38). The credential emitter no longer overwrites a hand-provisioned bootstrap password in credentials.xml on enrollment.

    Upgrade path. Same as 3.0.1: install the 3.0.2 modules alongside your existing ones, confirm each reaches Running, then uninstall the old ones. Module ids are unchanged, so this upgrade uses the same ids in place.

    Bundles for Ignition 8.1 and 8.3 are on the download page and at the v3.0.2 GitHub release.

  • 3.0.0
    2026‑09‑11

    Module ids move under com.greenguardusa; certificate enforcement, renewal and two-round enrollment; fleet on one common library

    3.0.0 is a coordinated rebuild of the whole fleet on one common 3.0.0 library. Every module we ship shares this library, with two breaking changes inside it: a new manual-acknowledgement mode for durable MQTT consumers, and a moved and narrowed outbound HTTP safety module (now DestinationPolicy). On top of that, SparkBridge gains real certificate enforcement, two-round enrollment, automatic certificate delivery and renewal, and every module id across the fleet is renamed to start with our own reverse domain, com.greenguardusa, to meet Inductive Automation's naming requirement.

    Certificate renewal. Renewal now runs as an explicit state machine on the edge: request a new certificate, receive the signed chain, prove it on a dedicated connection, switch the main connection over, tell the platform to promote it, then clean up. Any step can fail safely; on failure the edge retries or rolls back to its previous, still-valid certificate, verified by reading it back. Proven live end to end on our reference bench through repeated renewal cycles, including a deliberately exhausted cycle that rolls back correctly and an old certificate that is refused once a newer one has promoted.

    Enrollment. A site whose platform-side companion is not yet listening at boot now retries with increasing backoff and shows a live attempt count. Enrollment with no site name pre-configured is proven live end to end: a bare device with only a one-time code enrolls itself and receives a certificate automatically (zero-touch enrollment). When the platform's enrollment response is rejected, the reason is now surfaced and logged.

    DiskBuffer V3 and TRACE slice 2. The store-and-forward disk buffer and the lineage trace both advance to their next slice in this release; see the release notes for the full list.

    Licensing carries forward. A license key issued before this release keeps working: the platform recognizes old module identities and maps them onto their renamed replacements automatically, so existing keys are never reissued.

    Upgrade path. Install the 3.0.0 modules alongside your existing ones, confirm each reaches Running, then uninstall the old module ids. This is a side-by-side upgrade, not an in-place one; update any monitoring probe or dashboard URL that hard-codes the old REST route. Full operator checklist and breaking-change table in the release notes.

    Line coverage. Built and proven primarily on the 8.1 line. Every fleet 8.3 mirror is at 3.0 parity with its 8.1 line, gated and merged: SparkBridge, dnp3, iec104, ti505, SparkGantt, SparkAds, Spark61850, SparkVault, SparkSNMP, SparkNotify, SparkBacnet and SparkRecord. SparkS7 0.3.0 ships on both lines.

    Bundles for Ignition 8.1 and 8.3 are on the download page and at the v3.0.0 GitHub release.

  • SparkNotify 0.2.0
    2026‑09‑04

    SparkNotify: Discord and PagerDuty are finished channels

    SparkNotify 0.2.0 completes the Discord and PagerDuty channels. This release updates SparkNotify only; every other Spark product stays at its own version and does not need reinstalling. SparkNotify now versions independently of the SparkBridge fleet, so it moves off the 2.7.0 fleet bundle onto its own release.

    Discord. Rich embeds are on by default, with per-request username, avatar and thread overrides so one webhook can post under different identities or into a specific thread. Role mentions are explicit and fire only on High and Critical, so a routine alarm never pages a whole role. Discord rate limits are honoured on 429 with bounded attempts, cleared alarms post a follow-up notice once, and webhook URLs plus thread and role snowflakes are validated strictly at configuration time.

    PagerDuty. A full Events API v2 payload with dedup key, severity, source, component, group, class and custom details. US and EU regions, a minimum-priority filter, a configurable severity map, acknowledgement sync that mirrors an Ignition ack as a PagerDuty acknowledge, and resolve on clear. A failed trigger retains its UNRESOLVED state so it stays retryable, and trigger, acknowledge and resolve are applied in order per dedup key.

    Platform. All channel network calls run off the alarm scheduler thread, so a slow or hanging endpoint cannot stall alarm evaluation. Destination hosts are validated before every connect, refusing private, loopback, link-local, cloud-metadata and CGNAT targets by default.

    Version note. The 8.1 line briefly carried 0.1.2, an 8.1-only hot-upgrade fix build that never shipped on 8.3. 0.2.0 re-aligns both lines on one version and includes that fix.

    Email is deprecated. The Email (SMTP) channel is deprecated and scheduled for removal, because Ignition ships its own email notification module. The channel still works in 0.2.0. New deployments should use Ignition's built-in email notification profile, and existing Email profiles should be migrated before the removal release.

    Two known limitations carry into this release: an oversized numeric PagerDuty Retry-After retries with no delay rather than clamping, bounded by the attempt cap; and profile-level Discord clear idempotency has no regression test, a coverage gap rather than a known defect. DNS rebinding defence remains deferred.

    0.2.0 ships for both Ignition 8.1 and Ignition 8.3. Both bundles are on the download page and at the sparknotify-v0.2.0 GitHub release. The 8.3 line has no gateway on this network and ships on green suites plus packaged-module verification, as every prior 8.3 release has.

  • 2.9.0
    2026‑09‑06

    Enrollment slice 2 and capacity slice 2 finish the Track D pair

    2.9.0 updates the SparkBridge core modules only: Edge, Host, Provider and the authorization extension for external HiveMQ. Every other Spark product stays at 2.7.0 and does not need reinstalling. It is a drop-in module upgrade from 2.8.0, Provider then Host then Edge, and completes the two Track D items that were left in slice 1 at 2.8.0.

    Enrollment: certificate issuance and credential delivery. The Host holds a signing CA and returns a signed leaf certificate for each enrolled site's CSR; the Edge writes its keystore and reconnects through the existing hot-reload path. The Host also writes the site's broker credential straight into the extension's identities snapshot on redemption, one site at a time, so one bad legacy password never blocks another site's credential. A new reissue route mints a fresh password for an already-enrolled site. Enrollment now registers the site with FleetOps, including its certificate fingerprint and expiry, and Config > SparkBridge Edge > Settings on Ignition 8.1 gains an enrollment code field and a status row.

    Capacity: buffer depth, a degraded advisory, and sparklines. Two more Node Info/Store Forward * metrics carry each edge's buffer depth and a degraded flag; a new BUFFER_DEGRADED recommendation names a site whose buffer itself is degraded, ahead of suggesting a bigger one. /capacity/view adds inline sparklines for updates per second, headroom, and queue depth. The fleet-info watermark now clamps against a wrongly clocked edge instead of trusting its timestamp outright, and an estate upgrading Host before its edges keeps every edge's retention figure advancing during the transition.

    Security. ADMIN and WRITE routes now fail closed: before 2.9.0, an ADMIN route with no admin token configured could be satisfied by a lower-tier token. A lower tier's token no longer satisfies a higher tier under any configuration.

    New signing certificate. Modules are now signed with "SparkBridge Code Signing, GreenGuard USA," fingerprint 1D:72:68:08:69:94:7B:3B:3F:28:AD:C9:0F:F6:9A:3C:6D:76:FA:2F:87:37:C5:BE:9B:E3:9B:3D:D7:5F:F8:64. A gateway that has not seen it is prompted once, on the first module you install; accept it after checking the fingerprint against the certificate file in the release package.

    Honest limits. The broker does not yet require the client certificate at connect, so certificate issuance is a second factor carried alongside the password today, not yet enforced at the TLS layer. Enrollment still needs the edge name configured first, since a CSR has to name a subject before the Host has assigned the site an identity; a two-round exchange that removes this step is planned. There is no certificate renewal or revocation yet, so a technician re-enrolls the site to replace one nearing expiry. The 8.3 line has no Edge settings tab, since the 8.1-only config layer it is built on was removed on the 8.3 mirror at an earlier release; enrollment status on 8.3 reads from /status instead.

    Redeploy the HiveMQ extension if you run an external broker, and copy the identities file into the extension home after every enrollment batch: the extension reads its own snapshot of that file, not a live view of the Host's copy.

  • 2.8.0
    2026‑09‑04

    Capacity, enrollment, lineage, contracts and GitOps land on Host

    2.8.0 updates the SparkBridge core modules only: Edge, Host, Provider and the authorization extension for external HiveMQ. Every other Spark product stays at 2.7.0 and does not need reinstalling. Upgrading from 2.7.0 is a drop-in module upgrade in the usual order, Provider then Host then Edge, with no BIRTH-shape break, topic rename or broker-ACL change, and keys issued for 2.5.0 through 2.7.0 stay valid.

    Capacity intelligence. /capacity reports measured headroom and names the next expansion step, and /capacity/history returns the retained trend. BIRTH grows by two Node Info/* metrics carrying each edge's buffer and retention state; as in 2.4.0, a fleet sized close to its BIRTH byte cap should confirm headroom before upgrading.

    Zero-touch enrollment. A one-time code issued at /enrollment/issue lets a new site bootstrap its identity over a signed channel. A site becomes enrolled only once the response is durable, so a failed publish leaves the code redeemable. The file-RBAC role block in the shipped credentials template carries the two enrollment topics; it ships commented out, so uncomment it and adapt the identity. file-RBAC denies silently, and an edge missing those grants simply fails to enroll.

    Lineage, contracts and GitOps. /trace/:id/hops and /lineage expose the per-hop path of a sampled message over a durable ring that survives a restart. /contracts holds each prefix to the shape adopted from its first BIRTH and raises an alarm-able status tag on a violation. /gitops reconciles the gateway against a checked-out configuration bundle, with an approvals gate and an append-only audit trail; apply always publishes the configured bundle and refuses a directory override.

    Redeploy the HiveMQ extension if you run an external broker: upgrading only the module files leaves a stale extension behind. The extension list must report 2.8.0.

    2.8.0 ships for both Ignition 8.1 and Ignition 8.3. Both bundles are on the download page and at the v2.8.0 GitHub release.

  • 2.7.0
    2026‑09‑02

    Licensing: every paid module runs on Ignition's two-hour trial until a key names it

    2.7.0 is a licensing release, and it changes behavior for unlicensed gateways. Every paid Spark module now ships as a non-free module, so the gateway runs it on Ignition's standard two-hour module trial and Reset Trial on the gateway home page restarts the clock. When the trial expires and no verified key in data/sparkbridge-license.key names the product, the module pauses its data path and keeps its configuration and buffers: Edge publishes NDEATH and stops publishing while store-and-forward keeps capturing, Central publishes a retained OFFLINE state and closes its sessions, Provider refuses new broker connections, SparkFlow stops its dispatcher, historians stop ingest but keep serving queries, and drivers disconnect and mark tags out of service. A key dropped in after expiry lifts the pause within about thirty seconds with no restart; removing it re-pauses in the same window. Keys are bound to the gateway system name; keys issued through the shop work on any gateway. Keys issued for 2.5.0 and 2.6.0 stay valid unchanged. SparkLink, SparkCalc and SparkID stay free and are never paused. No BIRTH, topic, broker-ACL or configuration changes. An unlicensed production gateway that upgrades will pause two hours after the modules start: install the key before upgrading.

    Hardening and capacity: tiered route authorization, soft licensing, measured capacity, zero-touch enrollment

    2.6.0 is a hardening and capacity release. Status routes now sit behind a tiered authorization policy with READ, WRITE and ADMIN token tiers, and loopback trust is opt-in rather than assumed. Soft licensing is wired into Edge, Host, Provider and Flow through one signed key file per gateway, with entitlements for the wider Spark lineup. A review-fix lane closed several correctness gaps in shared code: bounded reads and a session-cardinality cap, a negative-alias BIRTH crash, a config envelope size cap, correct UINT32 PropertySet decode, a UNS teardown accounting race and a JSON-body read deadline. No BIRTH, topic or broker-ACL changes; from 2.5.0 this is a drop-in module upgrade.
