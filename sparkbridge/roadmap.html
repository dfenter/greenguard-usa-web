Public roadmap

What is planned, and what is already partly there

No dates. Each item states what ships today, what is being built, and what would make it done. Product pages describe only what is released; this page is the only place planned work appears.

CapabilityShips todayPlannedStatus
Capacity intelligenceHost /capacity reports its own ceiling from benchmark evidence and the shard count it runs; /fleet shows capacity headroom per edge; Prometheus metricsShipped in 2.8.0: per-site buffer health (outage coverage from each site's own store-and-forward figures, kept current between BIRTHs), a seven-day ingest trend at /capacity/history, and one expansion recommendation naming the layer to grow, the number behind it, and the benchmark row it rests on. Every figure is a measured lower bound. Proven live on the reference gateway 2026-09-04. Built for 2.9.0 (proven live 2026-09-06, not yet released): per-site buffer message depth and degraded flag on the wire, a degraded-buffer recommendation that names the site, sparklines at /capacity/view, and a clock-skew clamp on the refresh watermark; a 2.8.0 Edge keeps reporting to a 2.9.0 Host.Shipped 2.8.0, slice 2 built
Zero-touch enrollmentOne-time enrollment code: a new site bootstraps identity over a signed, TLS-required channel; credentials written owner-onlyShipped in 2.8.0: the Host answers the code itself, keeps a site registry, issues the site's broker identity inside the signed document, and writes the authorization scopes both brokers read. Enrollment sessions are confined to the two enrollment topics on HiveMQ and the embedded broker. Proven live 2026-09-04. Built for 2.9.0 (proven live 2026-09-06, not yet released): the Host issues a certificate for each enrolled site from its own CA, writes the broker credential and reloads the broker without a restart, registers the site with FleetOps, and the Edge settings page carries the enrollment field and status. Honest limit: the broker does not yet require the client certificate at connect; that enforcement and cert-to-identity binding are the next item.Shipped 2.8.0, slice 2 built
Data lineageSingle-metric trace inside Host: five hops from receipt to tag write, with per-stage timing, over an admin routeShipped in 2.8.0: a sixth hop at the MQTT client boundary, source timestamp kept apart from arrival time with the store-and-forward replay flag, consumer hops appended by historian and cloud adapters over a write route, a durable ring of the last 1,000 traces that survives a restart, and a lineage page that shows every stage with "not measured" where a boundary is not instrumented. Proven live 2026-09-04. Still to come: edge and broker hops, SparkVault and SparkInject instrumentation.Shipped 2.8.0
Data contractsSparkRecord validates records against a versioned schema and refuses narrowing changesShipped in 2.8.0: a namespace registry on Host (prefix, owner, required metadata, strict or additive or open), a shape adopted per node and device from its first BIRTH, and every later BIRTH held to it. Removals, type changes, suspected renames and missing metadata raise an alarm-able status tag, a Prometheus counter and a registry row; additive mode accepts additions and bumps the version. Proven live 2026-09-04. Still to come: bad-quality projection in strict mode, a settings tab, and a CI check command.Shipped 2.8.0
GitOps / Enterprise GovernanceSigned configuration bundles distributed fleet-wide with anti-rollback sequencingShipped in 2.8.0 in a first form: a bundle directory as the source of truth (one signed document per site, every document checked before signing), drift on the Host between the bundle and the version each site declares on its own BIRTH, apply to one site as a canary or to all with an approvals gate, rollback as an older bundle at a newer sequence, and an append-only audit trail. Proven live 2026-09-04. Still to come: the Git adapter with commit-signature verification, signature-based two-key approvals, and the policy documents.Shipped 2.8.0
