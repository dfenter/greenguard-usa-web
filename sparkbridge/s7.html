Situations This Solves

Each one is the same shape: equipment that already speaks a real protocol, kept out of Ignition by the lack of a native driver.

The situationWhat changes
Ignition 8.3 dropped symbolic S7 addressing
Any plant upgrading to 8.3 with S7-1200/1500 controllers on the floor.		 SparkS7 restores symbolic tag browsing on 8.3 the same way it worked before, so an upgrade does not force a rewrite of every S7 address into a raw DB offset.
Optimized block access blocks the classic driver
Sites running DBs with optimized access enabled, the TIA Portal default.		 S7comm-plus, which SparkS7 speaks alongside S7comm classic, reads optimized DBs by symbol name directly, without disabling optimization project-wide just to get a driver working.
DB.DBX offsets are hand-typed from an export
The integrator maintaining a spreadsheet mapping byte offsets to meaning.		 The symbol table is read from the CPU, so tags come in named the way the TIA Portal project names them, not as an offset someone has to remember.
A PLC program change breaks every hard-coded address
Anyone who has re-mapped a tag sheet after a DB was restructured.		 Symbolic addressing means a rename or reorder in the PLC program does not silently break the Ignition side; the driver follows the symbol, not the offset.

For your engineers

SparkS7 is a native Siemens S7-1200/1500 driver module for Ignition 8.1 and 8.3, speaking both S7comm classic and S7comm-plus. It reads the CPU's symbol table directly, including optimized-access DBs, and exposes tags by name rather than raw offset. A diagnostics folder reports negotiated PDU size and connection status. Early access; live proof and QA documents ship with the first release build.
