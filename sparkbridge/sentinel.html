What it does

Four axes, twenty-three rules

It works against any Sparkplug estate, not only one built on SparkBridge. The findings above came from auditing our own.

Connection posture

How the broker greets a stranger

Anonymous access, TLS configuration, certificate validation, retained-message accumulation. Where it cannot get a verdict it says so: when our own broker refused to let the auditor borrow an edge credential, that was reported as no verdict, not quietly recorded as a pass.

Identity hygiene

Who can publish what, exactly

Every role is expanded against the Sparkplug topic grammar rather than read as a string. That is how the wildcard above was caught: in spBv1.0/Group/#, the message type is the third token, so a grant that reads like data access silently contains command access.

Protocol and namespace

Whether the estate follows its own rules

bdSeq lifecycle, sequence continuity, BIRTH completeness, alias discipline, namespace shape. A report that only checks TLS misses the estate that is quietly losing values.

How it is kept safe

An auditor with no publish path

A tool that inspects a live plant must not be able to touch it. That is enforced mechanically.

Enforced, not promised

  • The passive analyzer is checked by walking its compiled bytecode for any reachable publish call. Not a text search: the word “publish” appears throughout the remediation advice.
  • Active probes exist, are off by default, and require an explicit flag.
  • The traffic generator used to test the rules lives in a separate source set, so that invariant can stay strict.
  • The safety document was written and committed before the tool was.

Calibrated against a rigged estate

  • A deliberately misconfigured broker was stood up with eight planted defects.
  • All eight surfaced. None were missed. It scored that estate zero.
  • Two rules were changed because of live evidence, including one that had been flagging every correctly working broker for its own $SYS retained topics.
Where it stands

It has audited two estates

Ours and a rigged one. A third, built by someone else, is what it needs next.

Done and measured

  • 23 rules across four axes; JSON and HTML reports; free and full profiles.
  • 43 tests, none of which need a broker.
  • Found four genuine defects in our own estate on its first clean run, including one critical.
  • Caught eight of eight planted defects on a rigged estate.
  • The critical finding is published rather than buried, and the fix shipped.

Owed before release

  • A third acceptance case: a third-party estate we did not build.
  • A continuous-monitoring gateway module, so an estate is graded on a schedule and not once.
  • Release discipline: signing, checksums, versioned rule set.
