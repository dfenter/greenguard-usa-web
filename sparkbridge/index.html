why

Sparkplug B for Ignition, Subscribed.

Most of the time the answer is “nothing changed”. That traffic grows with how many tags you have and how many systems want them, not with what the plant actually did. Sparkplug turns it around: a site sends a value once when it changes, and any number of systems can subscribe to it.

Polling

Cost grows with every tag and every dashboard

A central server asks every site for every tag, over and over. Adding a dashboard or a historian adds load at the plant. One real server carrying 40 sites sat at 50 to 75% CPU, used 14 GB of memory, and could not ride out a network outage.

Sending on change

Cost grows only with what the plant does

A site sends a value when it changes, stamped with the time it was read, and describes its own tags once when it connects. Anything that wants the data subscribes. Adding the next system becomes a subscription rather than a project.

modules

Four Modules at the Core

SparkBridge itself is four Ignition modules. Install only what a site needs. Each interoperates with any other vendor's Sparkplug software.

Edge

Publishes Ignition tag data as it changes, and keeps publishing into a disk buffer when the link drops. 250,000 tags per edge node, up to 8 nodes on one gateway.

Host

Subscribes to the namespace, learns each site's model from its birth certificate, and projects it into an Ignition tag provider. 500,000 wire metrics resident in under 4 GiB, measured.

Provider

Supplies the broker: embedded for a single node, or a managed HiveMQ CE companion for MQTT 5 and shared subscriptions. No connected-client tier.

Flow

Optional. Sparkplug Hyperscaled: streams every point in the plant to the whole company, live, lossless and replayable, with commands back under your control. New in 2.5.0. Details.

Full feature detail, wire behavior and outage semantics are on the products page. Reference architectures show where each module sits in a real estate.

included

Six Features, Not Six Products

These ship inside SparkBridge and are never charged for. Passage, SparkCalc, SparkID and SparkLink come with any Edge or Central license; Sentinel and FleetOps are features of SparkBridge Central.

Passage

A standards-based window onto your live plant data. Historians, SCADA, analytics and test tools you already own read it as is, with no bespoke connector per system.

SparkCalc

Derived plant metrics calculated in one place: rates, totals, efficiencies. One number, calculated once, used everywhere, instead of the same formula in a PLC, a dashboard and a spreadsheet.

SparkID

Access control for your plant data network. Who can read, who can send commands, and safe credential rotation. A read permission never quietly includes control.

SparkLink

Data cost visibility and control for remote sites on cellular and satellite links. Bytes per tag and per site, measured, not estimated, so a site stays inside its budget.

Sentinel Central

A security and health assessment of your plant data network. A score, ranked findings, the evidence and the fix for each. It observes and changes nothing.

FleetOps Central

One view of every gateway you operate: versions, configuration drift, certificates, backups. Authorize once, apply across every site.

The capacity row is a floor, not a peak. It is the lowest sustained rate seen across the 50,000, 250,000 and 500,000 metric tiers, measured all the way through projection to a value visible on a tag, which is what an operator actually sees. The commercial modules do not publish load or capacity benchmarks, so there is no figure to compare against.

The official examiner passes. The Eclipse Foundation, who publish the Sparkplug specification, also publish its test kit. The 2026-08-15 seed-240 session against 2.4.0 ran ten times with zero FAIL lines, 182 EDGE and 52 HOST assertions passed, and a single MAYBE against an optional SHOULD. It is scripted and repeatable on your own hardware. The formal Eclipse listing is a separate administrative step, still in progress.

820 automated tests stand behind it, including live gateway integration, property-based codec testing, corrupt-buffer and chaos suites, negative TLS tests, and load and endurance scenarios you can run yourself.

Security is the default, not a hardening exercise. An edge credential is bound to its own group and node, cannot publish commands at all, and cannot write another site's data. Decoding is bounded on every input path, API tokens are separated by read, write and admin and fail closed, and secrets live in a permission-restricted file rather than JVM arguments.

Detail lives on technology, the raw execution record on the TCK results page, and the whitepaper and specification in resources.
