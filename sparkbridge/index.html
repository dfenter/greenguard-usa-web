why

Data, Subscribed.

Most of the time the answer is “nothing changed”. That traffic grows with how many tags you have and how many systems want them, not with what the plant actually did. Sparkplug turns it around: a site sends a value once when it changes, and any number of systems can subscribe to it.

Polling

Cost grows with every tag and every dashboard

A central server asks every site for every tag, over and over. Adding a dashboard or a historian adds more load at the plant. One real server carrying 40 sites sat at 50–75% CPU, used 14 GB of memory, and could not ride out a network outage.

Sending on change

Cost grows only with what the plant does

A site sends a value when it changes, stamped with the time it was read. It describes its own tags once when it connects, so anything that wants the data just subscribes. Adding the next system becomes a subscription rather than a project.

Edge

Publishes Ignition tag data as Sparkplug, and keeps publishing into a disk buffer when the link drops.

250,000tags per edge node, and up to 8 independent nodes on one gateway

Discovery and capacity

  • 250,000 tag budgetScalar leaves and unfolded UDT members count against one budget. A UDT is admitted whole or skipped whole, never half.
  • Bulk chunked subscribe10,000 paths per chunk, so a large site subscribes without stalling the gateway's tag system.
  • Rescan recoveryA failed browse subtree is retried by full rediscovery. A pass that could not read the tree never retires devices on the strength of what it could not see.

Outage behaviour

  • Disk store and forward50 MB default buffer, batched fsync at about 2,697 messages/s durable; per-record fsync available where the trade is worth it.
  • True historical replayBuffered values keep their capture timestamps and carry is_historical, so a historian backfills the real curve instead of a block of arrival-time data.
  • Bounded reconnectPaho's 128-second backoff is capped to 10, so recovery after a WAN restore is bounded rather than arbitrary.

Modeling

  • Sparse TemplatesDefinitions deduplicated ahead of instances; BIRTH carries the full instance, NDATA only the members that moved, explicit null transitions retained.
  • Device modelingFolders at a configured depth become Sparkplug Devices with their own DBIRTH and DDEATH, hot-reloaded on rescan without disturbing the MQTT session.
  • Metadata foldingUnits, description and ranges ride the birth certificate as a PropertySet, taking roughly a third of points out of the steady-state stream while making the model more self-describing.

On the wire

  • Report by exceptionFractional deadband and a 100 ms coalescing window; NDATA is alias-only, so a metric name is paid for once per session.
  • Primary host lifecycleBirths are gated on the host's STATE, and a valid host-offline terminates the session and walks to the next server.
  • Write-back is deny by defaultDCMD is rejected unless a device/metric pattern opts it in.
  • Up to 8 edge nodesEach with its own transport, subscriptions, buffer and birth sequence state.

Host

Subscribes to the namespace, learns each node's model from its birth certificate, and projects it into an Ignition tag provider.

500,000wire metrics resident in under 4 GiB, measured. A consolidated 40-site estate fits with margin; fan-in above roughly eight busy edges is spread across brokers or shared consumers, both of which ship

Model and projection

  • Self-learning tagsThe model arrives in the birth certificate. Tags appear as sites come online; there is no central tag configuration to maintain or drift.
  • Template expansionTemplates expand into member tags, and folded metadata projects onto standard engineering properties: units, documentation, and the low and high range.
  • Aware-broker primingAgainst a Sparkplug Aware broker, a late-joining host learns the estate from retained certificates instead of asking every edge to rebirth at once.
  • Third-party edges welcomeAliases are optional in Sparkplug, and since 2.3.0 the Host accepts births and data from edges that never assign them. UINT32 is read unsigned from either legal wire field, in metrics, DataSet cells, properties and template parameters alike. Verified live against the Eclipse Tahu reference edge.

Scale

  • 500,000 wire metricsResident in under 4 GiB, with per-metric cost flat from 250,000 through 1,000,000, with no cliff to discover in production.
  • Sharded ingestPer-node order preserved while sites decode in parallel, with bounded queues and a gateway-wide byte budget that several connections cannot multiply.
  • Shared-subscription scale-outMQTT 5 consumers share one broker stream: about 20x delivered ingest with four consumers against one.
  • Simultaneous multi-serverA session on every configured server, retained STATE per server stamped with that server's connect time, and commands routed only to where the edge was last heard.

Correctness under failure

  • Rebirth with a cooldownA sequence gap asks for a rebirth once per node per window, so a lossy link cannot be amplified into a fleet-wide rebirth storm.
  • Death that means deathAn NDEATH stales the node and evicts its devices, but a death on one server does not retire a session another server is still delivering.
  • Confirmed write-backA command reports success when the edge reflects the commanded value, not when the broker accepts the publish.
  • Bounded decodingPayload size, metric count, template nesting depth, dataset cells and property entries are all capped on every input path.

Operations

  • Status and inventoryA live dashboard and a node inventory that says which sites are alive, dead, or stale, and how much of the model each carries.
  • Prometheus metricsWire metrics and projected leaves counted separately, replay volume distinguished from live data, and latency histograms.
  • Hot reloadConfiguration changes apply in about five seconds with no gateway restart.

Provider

Supplies the broker: an embedded one for a single node, or control of a HiveMQ CE companion for MQTT 5 and shared subscriptions.

No client tierCommercial brokers are commonly licensed by connected-client count. This one has no such dial.

Broker

  • Zero-config embeddedMoquette on loopback for a single node. Nothing else to install, and no MQTT 5 features to configure.
  • HiveMQ CE companionFor scale: MQTT 5, shared subscriptions and Sparkplug Aware certificates. The Provider stands aside and manages posture instead of binding the ports.

Identity

  • Per-site scopingAn edge credential is bound to one group and node. An unlisted edge user is denied outright.
  • Client-ID bindingA scoped credential must present its own deterministic client ID, so one site cannot evict another's broker session.
  • Host and edge are splitEdge identities cannot publish NCMD, DCMD or STATE at all. Command injection is structurally unavailable, not merely discouraged.

Application topics

  • Denied by defaultOn the SparkBridge broker, UNS, file-transfer and bridge topics are authorized per identity by prefix, so one site's credential cannot forge another site's data. On external HiveMQ the publish and subscribe authority is file RBAC, and the preflight generates the permission blocks for it.
  • Level-bounded prefixesMatching respects topic boundaries, and a filter may wildcard below a granted prefix but never across or above it.

Transport and posture

  • TLS and mTLSHostname verification is mandatory; disabling it requires an explicit development-only flag that has no production use.
  • Read-only posture pageThe effective security settings are shown in the gateway UI and cannot be widened from the web at all.
  • Runs on Ignition 8.1.19 and newerThe data path is compiled against the 8.1.0 API and the bytecode targets Java 11, so nothing reaches for a later method or a later JVM. Runtime-verified on 8.1.38.

conformance

Tested Against the Official Suite

The Eclipse Foundation, who publish the Sparkplug specification itself, also publish its official examiner: a test kit that watches a product on the wire and fails it for any deviation from the standard. Here is what that looked like, in plain terms.

What was tested

Not a simulation and not a paper claim. A complete live system was stood up, broker, host and edge together on a real Ignition gateway, and the official kit connected to it like any other participant, watching every message. It then put the system through the situations that break integrations in the field: publishing complex equipment models with parameters and datasets, receiving and acting on commands, losing the central server mid-session, and being forced to walk from one broker to another without losing its devices.

How it judges

The kit reads every byte the modules put on the wire and checks it against the specification: message order, sequence numbers, birth and death certificates, retained state, timing. There is no partial credit; a single wrong byte or out-of-order message fails the scenario.

The result

The published record is 346 assertions executed, 346 passed, zero failed, across every edge profile and the host session profile. The suite was re-certified against 2.4.0 code on 2026-08-15, seed 240: ten runs, 182 EDGE assertions passed and 52 HOST assertions passed, every profile OVERALL PASS and zero FAIL lines in the whole session. Every run is scripted and repeatable, and the nine-profile session is now a single command, so the result can be reproduced on your own hardware rather than taken on trust.

What this is not

It is not yet a formal certification. The official listing with the Eclipse Foundation is a separate administrative step, membership, paperwork and a published report, and it is the next step on the roadmap. The engineering half, passing the examiner, is done and repeatable today.

The full execution record is published, raw and unedited, at the TCK results page; the whitepaper carries the analysis.

security

Security as the Standard

The Sparkplug specification does not say how to handle security, so it leaves the important questions open: what stops a hacked site from pretending to be another one, or sending commands to your equipment? Here is what SparkBridge does about it.

ControlHow it behaves
Per-site identity scopingAn edge credential is bound to its own group and node. An unlisted edge user is denied; unscoped credentials require an explicit development-only opt-out.
Command injectionStructurally prevented. Edge identities cannot publish NCMD, DCMD or STATE. Proven live against the deployed broker ACL.
Application topicsOn the SparkBridge broker, the UNS tree, file-transfer manifests and bridge traffic are authorized per identity and denied by default, so one site's credential cannot forge another site's data. On external HiveMQ the same separation is expressed as file RBAC, generated for you by the migration preflight.
API authenticationSeparate read, write and admin bearer tokens, fail-closed. Query-string tokens are rejected on sensitive routes.
Malformed inputBounded decoding on every path: payload size, metric count, template nesting depth, dataset cells and property entries, plus a 50,000-case fuzz of the decoder.
Secret handlingA permission-restricted file, not JVM arguments visible to any local user through ps. A configured but unreadable secrets file fails the module closed.

Assurance base: 531 automated tests including live gateway integration, property-based codec testing, corrupt-buffer and chaos suites, and negative TLS tests; load and endurance scenarios you can run yourself; and repeated independent adversarial review cycles whose findings are fixed, tested and re-verified rather than filed.
