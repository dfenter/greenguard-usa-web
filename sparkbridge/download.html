package contents

What Is In the Zip

Everything needed to install, verify and configure the suite, and nothing that needs a second download.

Four signed modules

SparkBridge-Provider.modl owns the broker: it runs the embedded Moquette for a zero-configuration first install, or stands down and lets an external HiveMQ CE own the ports. SparkBridge-Host.modl decodes Sparkplug into a managed Ignition tag provider. SparkBridge-Edge.modl publishes a folder of gateway tags as Sparkplug. Install them in that order, because the Provider has to be running before the Host subscribes and before the Edge publishes. SparkBridge-Flow.modl, new in 2.5.0, is optional: it carries everything the Host decodes onto NATS/JetStream as a unified namespace, with last-known value and lifecycle in a KV bucket, a confirmed-write command path back to the edge and a Perspective dispatcher fed from the stream. Install it last, only if you run a nats-server, and read docs/FLOW_MODULE.md in the bundle first.

The broker authorization extension

A HiveMQ extension, shipped as its own zip. It binds each credential to the client ID derived from its scope, so one site's credential cannot present another site's client ID and evict that session, and it refuses an unauthorized Last Will at CONNECT before a session exists. It also judges PUBLISH and SUBSCRIBE, deferring rather than allowing where it has no opinion, so file RBAC keeps the final authority. You need it only if you run external HiveMQ, and if you do run it, it upgrades in the same maintenance window as the modules.

The Perspective status project

sparkbridge-perspective-2.5.0.zip is an importable Perspective project that puts the suite's status on a screen: node health, per-node SLO statistics and the signed fleet configuration each site is running, with nothing to build by hand.

Checksums and the signing certificate

SHA256SUMS.txt covers the modules, the extension and the Perspective project, and the same values are published on this page so you can verify the delivery against a source that did not arrive in the same email. sparkbridge-signing-cert.pem is the certificate the modules are signed with: print its fingerprint with keytool and compare it against the acceptance page the gateway shows you on first install.

The documents you install from

QUICKSTART.md is a first run in two sessions: Sparkplug flowing on one gateway with the embedded broker in about twenty minutes, then external HiveMQ with TLS, file RBAC, separate host and edge identities and the authorization extension in another thirty-five. INSTALL.md is the reference walkthrough, including the upgrade path and the production checklist. RELEASE-NOTES-2.5.0.md is what changed and what an upgrade requires of you.

The license

license.html is the end user license agreement, and it is also what the gateway displays for acceptance when the module installs. A module whose license was never accepted stays quarantined, so it is worth reading the copy in the package before you are looking at it in a dialog.

The bundle also carries BUNDLE-SHA256SUMS.txt, generated over every file above, so one command verifies the whole delivery rather than only the binaries. The checksum of the bundle zip itself is published in the table below as well.

the trial

Two Hours, Reset as Often as You Like

The same trial mechanism every Ignition module uses, with no separate key to request and no expiry date on the calendar.

Install the modules and they run on Ignition's standard two-hour trial. When the two hours are up all four modules pause, store-and-forward keeps capturing rather than dropping what it was holding, and clicking Reset Trial on the gateway resumes them with no restart. There is no limit on how many times you may reset it, so a bench that gets picked up on a Tuesday and again a fortnight later never runs out, and there is nothing to renew or re-request in between.

Two hours is enough for the whole quickstart with time to spare, and it is enough to answer the questions that actually decide the purchase: does it hold your tag count, does the store-and-forward buffer survive the link you have, does the projection land where you expect it in the tag browser. What it is not built for is an unattended soak. For that, or for anything that has to survive a weekend without a person at the keyboard, tell us and we will sort out an arrangement.

Paid activation is coming through Inductive Automation's third-party module program. That is the same licensing surface as any other commercial Ignition module, activated against your gateway the way you already activate modules. Until it lands, the trial is the whole story: there is no interim license file, no dongle, and nothing you can buy today that changes what the modules do.

before you install

What It Needs

The floor is genuinely low. The optional companion broker is the only thing with dependencies of its own.

RequirementDetail
Ignition 8.1.19 or newerThe floor is the first build carrying the config-page API the gateway tabs use. Runtime verification is on 8.1.38. If a config page is ever unavailable, every setting is still reachable as a system property or through the REST API.
Java 11 or newerIgnition bundles its own, Java 11 through 8.1.33 and Java 17 from 8.1.34. The modules target Java 11 bytecode so they load on either.
A gateway you can restartSystem properties live in ignition.conf and are read at startup. The Edge's source folder is the exception: it is a config page setting that applies live.
keytoolFor the TLS keystore. It ships with every JDK and with the JRE Ignition bundles.
For external HiveMQ onlycurl, unzip, python3 and a JDK 11 or newer on the broker host. The embedded broker needs none of it, which is why the first session of the quickstart uses the embedded one.

The modules are signed with a self-signed SparkBridge certificate today, so the gateway quarantines the first module and shows a certificate acceptance page. Accepting once covers all four. An Inductive Automation issued certificate installs with no prompt at all, and moving to one is a drop-in change on our side.
