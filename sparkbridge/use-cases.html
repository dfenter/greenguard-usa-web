Use cases

Where it is used

The same architecture works for a wellhead, a bottling line or a pump station. Here is where it earns its keep.

wide area

Remote Sites, Expensive Links

Cellular, satellite or radio links. You pay for the data, the connection drops, and it always drops during the event you most needed to record.

The problem

Polling wastes the connection

Polling spends your data allowance asking questions whose answer is usually “nothing changed”, and an outage leaves a gap in the history that no later poll can fill.

What changes

Send changes, store during outages

Normal traffic tracks what the plant is doing. If the link drops, the site saves readings to disk with their original timestamps and sends them when it reconnects, so the history shows the real curve rather than a flat line and a jump.

consolidation

Many Sites, One Server

A real example: one central server carrying 40 sites, sitting at 50–75% CPU, using 14 GB of memory, unable to ride out a network outage, and getting worse every time someone added a dashboard.

Sizing

280k–300k metrics

That estate's consolidated published metrics, sized from real gateway backups.

Envelope

500k in under 4 GiB

The measured single-host capacity, with per-metric cost flat to a million. The fleet fits with margin on every dimension.

Consumers

Cost does not grow

Adding a dashboard, a historian or an ML pipeline adds a subscriber, not load at the source.

uns

One Source of Plant Data

This just means every system reads the same up-to-date picture of the plant from one place. You get it by publishing properly, not by buying something else.

Discovery

The namespace populates itself

Each site describes itself at birth, so a new consumer subscribes and discovers the estate rather than being configured for it.

Dual publish

Sparkplug and JSON

The same values a second time on a readable ISA-95 style path for consumers that will never speak protobuf.

Isolation

Per-site write scope

Application topics are authorized per identity and denied by default, so a site can write its own subtree and nobody else's.

analytics

Feeding Dashboards and AI

All of these need the same thing: a complete, current, cheap-to-read picture of the plant, including a clear signal about which values can no longer be trusted.

Why this matters more than speed

You know which values are stale

A model trained on values that silently went stale learns the wrong thing. Sparkplug marks the loss of a session explicitly, and SparkBridge passes per-metric source timestamps through to the tag system rather than stamping arrival time, so backfill lands on the real curve.

Why it stays affordable

Adding another consumer costs nothing

An architecture whose cost scales with process activity rather than tag count and consumer count is a durable advantage when compute and data-centre capacity are the constrained resources.

ot it

Plant to IT, Safely

The real security question is not “can we get data out of the plant”. It is “if one site is compromised, what can it do to the rest”.

ConcernHow the architecture answers it
Inbound firewall rulesThe edge connects outbound to the broker. No inbound port into the plant network is required for data to flow.
A compromised site publishing as anotherAn edge credential is bound to its own group and node; an unlisted user is denied, and the client ID is bound to the credential.
A compromised site issuing commandsEdge identities cannot publish NCMD, DCMD or STATE at all. Command injection is structurally unavailable rather than discouraged.
A compromised site forging enterprise dataApplication topics (the UNS tree, file-transfer manifests) are authorized per identity and denied by default.
Credentials on the boxSecrets live in a permission-restricted file, not in JVM arguments visible to any local user through ps.
