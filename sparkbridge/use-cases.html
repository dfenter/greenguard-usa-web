wide area

Remote Sites, Expensive Links

Cellular, satellite or radio links, where you pay for the data and the connection drops.

The problem

Polling wastes the connection

Polling spends your data allowance asking questions whose answer is usually "nothing changed." An outage leaves a gap in the history that no later poll can fill. Nobody can name the tag that is actually spending the money. In a real three day capture, one vibration tag with no change threshold set was taking 50.7% of a site's monthly budget, at 47 times the next largest consumer.

What changes

Send changes, store during outages

Normal traffic tracks what the plant is doing. If the link drops, the site saves readings to disk with their original timestamps and sends them when it reconnects. The history shows the real curve, not a flat line and a jump. The budget becomes a measured list you can act on. Readings you mark critical are protected in the sending path itself, so no budget rule can quietly degrade them.

Products in play: SparkBridge Edge, SparkLink for the data budget, and SparkVault if the history has to survive the outage as well as the link.

Many Sites, One Server

A real example: one central server carrying 40 sites, sitting at 50 to 75% CPU, using 14 GB of memory, unable to ride out a network outage, getting worse every time someone added a dashboard.

280k to 300k metrics. That estate's consolidated published metrics, sized from real gateway backups.

500k in under 4 GiB. The measured single-host capacity, with per-metric cost flat to a million. The fleet fits with margin on every dimension.

Cost does not grow with consumers. Adding a dashboard, a historian or an ML pipeline adds a subscriber, not load at the source.

The estate stays visible. Forty gateways is forty version numbers, forty certificate expiries and forty backup schedules. On a 40-site rig, one authorized certificate rotation reached every site in 937 ms, and the same instruction captured and replayed was refused by all forty.

Products in play: SparkBridge Host and SparkBridge Edge, with FleetOps once the site count is too large to track by hand.

One Source of Plant Data

This just means every system reads the same up-to-date picture of the plant from one place. You get it by publishing properly, not by buying something else.

The namespace populates itself. Each site describes itself at birth, so a new consumer subscribes and discovers the estate rather than being configured for it.

Readable, not just fast. The same values are also published on a plain, readable path, for people and tools that were never going to read a machine format.

One number, calculated once. Efficiency, throughput and cost per unit are computed in one place and published back as plant data, each value carrying the time of its oldest input and going bad when any input does. That is what makes a reported figure defensible.

Everything you already own can read it. The same live values are served to the historian, SCADA package or analytics tool you are not going to replace, with source timestamps intact.

Products in play: Passage for the systems you already own, SparkCalc for the derived numbers, SparkVault for the history behind them, and SparkInject when the warehouse is the destination.

Plant to IT, Safely

The security question that matters here is what a compromised site can do to the rest of the estate.

ConcernHow the architecture answers it
Inbound firewall rulesThe site connects outbound only. No inbound port into the plant network is required for data to flow.
A compromised site publishing as anotherEach site has its own identity, bound to its own name. An unlisted identity is denied outright.
A compromised site issuing commandsSite identities cannot send commands at all. Command injection is structurally unavailable, not just discouraged.
A compromised site forging enterprise dataEvery identity is authorized per data path and denied by default, whether the deployment is on our system or a third party's.
Credentials on the boxSecrets live in a permission-restricted file, not in a place any local user on the machine can read.
Rules typed by handPermissions are generated from stated intent, one line per action, and the change is shown as a difference before it is applied. A change that would lock you out of your own system is refused.
Proving any of this to an auditorA scored assessment with ranked findings, the evidence behind each one and the fix. The first run against our own estate found four genuine defects, one of them critical.

Products in play: SparkID for the permissions, Sentinel for the assessment and the evidence.
