What it does

A historian, and then a DVR

Two jobs from one store. Recording the estate is the ordinary half. Playing it back is the half nobody else offers.

Record

Passive, so nothing changes upstream

SparkVault subscribes to the Sparkplug stream the same way a second host would. It reads alias tables out of every BIRTH, honours is_historical on backfilled values, and writes deaths as Bad_Stale markers. No edge node is reconfigured, and no publisher learns it is being recorded.

Read

It answers where Ignition already asks

The store registers as a tag history provider called SparkVault, so trends, reports and scripts reach it through the same call they already make. Browse comes from a 30-day distinct-tag query behind a one-minute cache; queries stream on a JDBC cursor rather than loading a window into memory.

Replay

Plant replay, in two modes

Historical re-publish puts stored values back on the bus flagged historical, on their original timestamps, for a consumer that missed them. Simulation replay re-stamps them and paces at 1×, N× or as fast as the link allows, for testing a dashboard against a real day.

How replay stays safe

Replay can never be mistaken for the plant

A DVR that can impersonate a live edge node is a hazard, not a feature. The identity rewrite is enforced in the rail, not left to configuration.

Enforced in code

  • Replay publishes under its own Replay/ namespace, never the original group or edge node id.
  • It carries its own bdSeq lifecycle, so a host counts it as a separate edge node and no live session is disturbed.
  • The rewrite happens in the rail every message passes through. A misconfiguration cannot route around it.

Proven on a real outage

  • A gateway sat paused for four hours and eleven minutes with store-and-forward capturing.
  • On resume the backlog replayed and landed on its original timestamps, flagged historical, while the live tail kept growing.
  • Nothing was lost and nothing was restamped. The recorded curve has a real gap-then-fill, not a wall of values at one instant.
Where it stands

Feature complete, and not yet signed

SparkVault runs on a production gateway today against a real Timescale instance. Here is exactly what is done and what it still owes before it earns a release.

Done and measured

  • Ingest, read path and replay all shipped and running on a live 8.1.54 gateway.
  • Versioned schema with a migrator that takes an advisory lock, so two gateways cannot race a migration.
  • A database outage spills decoded rows to disk and replays them before new data, preserving source timestamps.
  • 53 unit tests plus 12 tests that run against a real TimescaleDB.
  • Passed an adversarial external code review; all ten findings fixed the same night.

Owed before release

  • A multi-day soak at estate scale.
  • A licence gate.
  • A signed release with checksums and upgrade notes.
  • Continuous aggregates and retention policy defaults.
