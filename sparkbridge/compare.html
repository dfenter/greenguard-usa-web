Architecture comparison

What changes when Ignition grows past a few sites

Five sites can be run almost any way. Forty cannot. This page compares three ways to build a distributed Ignition estate on the problems that appear with scale: fan-in, backend count, outages, timestamps, adding a consumer, and running the fleet afterwards. It is written for the engineer who will own the result, and it names what each approach does well.

the three shapes

Traditional, Module-Based MQTT, SparkBridge

The same forty sites, drawn three ways. Every box is a server somebody has to license, patch and watch.

Every consumer is another Gateway Network connection into every site, or another backend that holds its own copy of the estate. Site count multiplies backend load; consumer count multiplies site load.

SparkBridge 
40 x Edge (publish once, buffer to disk)
      |
Provider HA pair (identity, policy, routing)
      |
Host pool (one namespace, shared consumers)
      |
+------+--------+--------+---------+
Vault  Record  Passage  Inject  Your tools

Sites publish once. Consumers subscribe at Host. Adding a consumer, a site, or a Host changes one layer and leaves the other two alone.

Module-based MQTT for Ignition sits between the two: sites publish over Sparkplug and buffer through outages, which removes polling and most of the fan-in. What it leaves to custom engineering is everything after the transport: consumer scale-out, provisioning, configuration drift, fleet health and security policy. MQTT is the transport. Operating the estate is the problem.

add a consumer

Adding a Consumer Without Touching Forty Plants

Day one 
40 sites --> Provider --> Host --> Existing application
A year later 
40 sites --> Provider --> Host --> Existing application
                                --> SparkVault (history)
                                --> SparkInject (warehouse)
                                --> Passage (OPC-UA clients)
                                --> Analytics and AI

No changes at the forty sites. Each new consumer is a subscription at Host or a module on it. In the traditional shape each of those four lines is a new backend or a new set of site connections, and usually a project with a budget line.
