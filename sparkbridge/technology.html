How it works

MQTT moves data around. Sparkplug adds what the data means, which site sent it, and whether it can still be trusted. Here is how that works.

lifecycle

The Life of One Connection

MQTT moves messages but says nothing about what is inside them. Sparkplug defines the whole life of a connection, and every guarantee it gives you is delivered by one specific message in that life. Read it top to bottom: this is the order it happens on the wire.

  1. STATE

    The server speaks first

    The host announces itself with a retained STATE message, so any site connecting later knows the consumer is alive before it says a word. Edges gate their births on it: a host restart never triggers an estate-wide stampede of uncoordinated births.

  2. NBIRTH

    The site introduces itself, completely

    The edge publishes its whole model in one birth certificate: every point with its name, datatype, engineering units and current value, stamped seq=0 and a session number that identifies this connection uniquely. Consumers learn the model from the stream itself. There is no schema registry to fall out of date.

  3. DBIRTH

    Equipment arrives as whole objects

    Each device under the node announces its own metrics: a pump, a loop, a skid crosses the wire as an object with named members, not a bag of loose points, and can be retired later without disturbing the rest of the node.

  4. NDATA

    Then, only what changes

    From here on, only changed values move, alias-only on the wire because the metric name was paid for once at birth. Steady-state load tracks what the process actually did, not how many tags exist. That is a structural property of the protocol, not a tuning parameter that decays.

  5. seq

    Every message counts itself

    A rolling sequence number rides every message, so a consumer can prove it missed something rather than quietly carrying a hole. A gap makes the host ask for the model again, rate-limited per node so one lossy link cannot amplify into a fleet-wide storm.

  6. NCMD

    Writing back is confirmed at the plant

    Commands flow the other way on the same connection. SparkBridge reports a write as successful when the site reflects the commanded value, not when the broker merely accepts the publish.

  7. NDEATH

    Silence is never mistaken for health

    The death certificate is registered with the broker as an MQTT Will at connect time, so it is published even when the site cannot say goodbye. Every consumer knows within seconds, and values are marked stale instead of being left to look current.

  8. NBIRTH

    And the loop closes

    When the site returns it simply births again with a new session number, and everything above repeats. Recovery is not an add-on procedure; it is the same three messages the protocol always speaks.

The Unified Namespace, Explained

One up-to-date picture of the plant that every system reads from. You get it as a result of publishing properly, with no second project to fund.

What comes as standard

It builds itself

Because each site describes itself when it connects, the picture fills in as sites come online. Anything new (a dashboard, a historian, an analytics tool) subscribes and finds what is there, rather than needing to be configured tag by tag.

What SparkBridge adds

Plain JSON as well as Sparkplug

The Edge can also send the same values as plain JSON on a readable path, for tools that cannot read the Sparkplug format. Sparkplug for the systems that need types and connection state; JSON for the ones that just need a simple feed.

The Standard Is Only the Start

Conformance is table stakes. What decides an estate's operating cost is everything the standard leaves open: buffering, scale-out, identity scoping, hot reload, and observability.
