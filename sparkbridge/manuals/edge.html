SparkBridge Edge

Edge is a Sparkplug B edge node module for Ignition. It subscribes to a site gateway's tag layer, applies report-by-exception with batching and deadband, publishes BIRTH/DATA/DEATH, and buffers to disk through a broken link so a lost session cannot drop data.

Overview

1. Overview

Edge runs on the gateway physically closest to the equipment. It reads the gateway's own tag tree, applies report-by-exception (only publish what changed), and sends Sparkplug B BIRTH, DATA and DEATH messages to a broker managed by a SparkBridge Provider. It is not a broker and not a historian: it has no opinion about what happens to the data once published, and it does not decode anyone else's Sparkplug traffic. A durable store-and-forward buffer on disk means a broken MQTT session does not lose data; queued messages replay on reconnect.

Edge is the first leg of the SparkBridge backbone: Edge publishes, Provider routes, Host decodes. Install Edge after Provider and Host are running.

Requirements

2. What You Need

Ignition8.1.19 or newer on the 8.1 line, or 8.3 (separate build). A gateway that can be restarted at will during install.
JavaCompiles against the Ignition 8.1.0 API, targets Java 11 bytecode. No separate JRE install needed beyond the one Ignition ships with.
Gateway roleAny Ignition gateway at the site whose tags need to leave the site. Not the Host gateway (Edge and Host are typically different gateways, though they can share one for a single-node setup).
NetworkOutbound reach to the Provider's broker: TCP 1883 (plaintext) or 8883 (TLS) by default.
Other SparkBridge modules requiredA running Provider (embedded or external HiveMQ CE) that Edge can publish to. A Host is not required for Edge to publish, but nothing decodes the stream without one.
Install

3. Install

  1. Download the release bundle for your Ignition line from the download page: SparkBridge-Provider.modl, SparkBridge-Host.modl, SparkBridge-Edge.modl, plus SHA256SUMS.txt and sparkbridge-signing-cert.pem.
  2. Install order matters: Provider, then Host, then Edge. In the gateway, go to Config > Modules > Install or Upgrade a Module and upload SparkBridge-Edge.modl last.
  3. The gateway checks the module's signature against the shipped certificate on upload. Accept the certificate and license once.
  4. Confirm Config > Modules shows SparkBridge Edge state = Running.

Upgrade every installed SparkBridge module together, from the same release bundle, in the same maintenance window. Host, Edge and Provider agree on which settings key each of them owns; a gateway running mixed versions can disagree on ownership for a key like hostId or foldtarget and silently misbehave.

License

4. License

FilePer-gateway license key at <data>/sparkbridge-license.key.
Re-check intervalEdge re-checks the key file every 30 seconds. Installing, replacing or removing a key takes effect with no restart.

From release 2.7.0, Edge runs on Ignition's standard two-hour module trial (the gateway's Reset Trial button restarts the clock). When the trial expires with no verified key naming the product, Edge publishes NDEATH and stops publishing, while its store-and-forward buffer keeps capturing underneath. A key dropped in after expiry lifts the pause on its own within the 30-second re-check, no button press and no restart. A verified key overrides the trial entirely.

Configure

5. Configure

Config > SparkBridge Edge > Settings. Set source to the tag folder to publish, for example [default]Plant/Line1. Edge polls its settings every five seconds and rebuilds its node runtime when edge-owned settings change; no restart is required. Every key below is Edge-owned: Edge is the only module that ever writes it, and every one hot-reloads on that five-second poll.

SettingMeaning, default
sourceTag subscription root. Default [System]Gateway/Performance.
nodesExplicit group,edge,source;… runtime list, up to 8. Empty falls back to one implicit Ignition/Gateway runtime.
batchmsNDATA batch window, milliseconds. Default 100.
deadbandPublish deadband fraction. Default 0.0.

unsprefixApplication topic prefix used by the UNS mirror. Default sparkbridge.
foldFolds UDT property members into the published Template. Default off. Must agree with the Host tab's Fold Target setting; changing one without the other silently loses the property mapping.
foldmembersName patterns matched for folding. Default Units,Description,Address*,IO_Loc*,Number,PV_L,PV_U.
primaryHostHost application id this edge watches for STATE. Must match the Host tab's Host Id. Default SparkBridge.
maxtagsDiscovery cap on tag count. Default 250000.
subchunkSubscription chunk size. Default 10000.

Edge-only identity and enrollment stay as -D system properties, not on this page: sparkbridge.edge.username, sparkbridge.edge.password (secrets file, never the command line), and sparkbridge.enrollment.code (one-time first-boot code against Host; Edge clears it after success).

Operate

6. Operate

Day to day, Edge needs no attention once BIRTH is confirmed. Watch the gateway log for repeated NDEATH/rebirth cycles, which usually mean a flapping network link rather than a SparkBridge problem.

On a link loss, Edge keeps publishing into its store-and-forward buffer on disk rather than dropping data; queued messages replay in order once the session reconnects. On gateway restart, Edge rebuilds its runtime from the last saved settings and re-publishes a fresh BIRTH with a new bdSeq.

SparkLink (bundled with Edge) shapes deadbands and publish intervals against a measured byte budget on metered links, with a fixed set of metrics exempt from any degradation.

Verify

7. Verify

Check the gateway log for the startup and BIRTH lines:

SparkBridge Edge: built 1 runtime(s), generation 1
SparkBridge Host: BIRTH Ignition/Gateway (N metrics)

A second BIRTH ... (N metrics) line with a changed metric count confirms a settings change was picked up. On the Host side, expand the managed tag provider in the Designer or gateway tag browser and confirm values update.
