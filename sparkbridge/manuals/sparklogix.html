SparkLogix

SparkLogix is an Ignition device driver that connects directly to Allen-Bradley ControlLogix and CompactLogix controllers over EtherNet/IP. It exists because Ignition's built-in Logix driver reads slowly and falls over on large or restricted tag sets: SparkLogix browses UDTs directly, plans reads per tag, and never lets a restricted tag block the rest of the read.

1. Overview

SparkLogix is a native Logix driver, not an add-on to Ignition's built-in one. It talks straight to the controller over EtherNet/IP; it does not need a translator box or an OPC server in front of the PLC. It is a standalone driver: it does not require any other SparkBridge module to run, though it can feed a Sparkplug B backbone through SparkBridge Edge like any other OPC UA device.

Module id: com.sparkbridge.sparklogix.

2. What You Need

  • Ignition 8.1.x (legacy driver API) or Ignition 8.3.x (managed-node API); these are separate module builds.
  • Java 17.
  • A ControlLogix or CompactLogix controller reachable over EtherNet/IP, firmware v16 or later. Micro8xx and 5000-series controllers are lower-priority targets on the same CIP core.
  • No other SparkBridge module is required. SparkLogix is licensed and runs standalone.

3. Install

  1. Download the release bundle for the target Ignition line (8.1 or 8.3) from the download page or the GitHub releases page.
  2. Gateway web UI > Config > Modules > Install or Upgrade a Module, upload sparklogix-<version>-ign83.modl (8.3) or the matching 8.1 build.
  3. Accept the certificate if the gateway warns about an untrusted signer.
  4. Confirm Config > Modules shows the module active with module id com.sparkbridge.sparklogix.
  5. To upgrade, install the new version over the same module id without uninstalling the old one first; existing devices and settings are retained.

4. License

FilePer-gateway license key at <data>/sparkbridge-license.key.
Re-check intervalEvery 30 seconds; no restart needed to apply, replace, or remove a key.

From release 2.7.0, every SparkBridge module runs on Ignition's standard two-hour module trial (the gateway's Reset Trial button restarts the clock). A verified key overrides the trial entirely and the trial clock is then ignored. Drop the key at <data>/sparkbridge-license.key; each module re-checks the file every 30 seconds, so installing, replacing, or removing a key takes effect with no restart.

5. Configure

Config > OPC UA > Device Connections > Create new Device > the SparkLogix Logix device type. The settings form has five categories: Communications, Timeouts, Probe Options, Redundancy, Advanced.

SettingMeaning, default
Network AddressDNS or IP of the first hop, optional :port.
Route PathSubsequent hops, for example 1,0 for a ControlLogix backplane slot; blank for an on-board Ethernet port.
Use Connected / Allow BatchingClass 3 connected messaging and Multiple Service Packet batching of small requests.
Use Instance IDsOff by default. Leave off; the instance-ID/symbolic fallback path is not independently field-verified yet.
Enable Class 1 CyclicOff by default.
Change DetectionOn by default, tag-database change polling.
Persist Tag DatabaseOn by default.
Verify WritesOff by default.

6. Operate

Once CONNECTED, SparkLogix maintains its own tag database from browsing the controller and plans reads per tag rather than as one monolithic scan, so a restricted or faulted tag does not stall the rest of the read. With Change Detection on (default), the driver polls the controller's tag database for changes and rebuilds affected parts of its plan without a device restart.

On a network drop, the device reports no communication and reconnects to GOOD on its own once the network returns; no gateway restart is required.

7. Verify

  1. Start the device and confirm it reaches CONNECTED and the first probe populates the tag database.
  2. Browse or type a tag path, for example an array member such as Entity.Params[0], and confirm distinct values per element (the array sentinel regression check).
  3. Disconnect the controller network briefly and confirm the device reports no communication, then reconnects to GOOD without a gateway restart.

8. Troubleshoot

SymptomCause / fix
Device never reaches CONNECTEDCheck Network Address and Route Path; a ControlLogix behind a backplane needs the slot in Route Path (for example 1,0), not just the IP.
Array elements all read the same valueThis is the array sentinel regression the verify step checks for; confirm you are on the current release and re-run the array-member check above.
Instance-ID addressing behaves oddlyLeave Use Instance IDs off; this fallback path is not yet independently field-verified.
