SparkRecord

SparkRecord takes structured records off Sparkplug, MQTT and NATS, manages their SQL schema automatically, persists them exactly once, and maintains a per-stream SHA-256 audit chain over the committed rows.

1. Overview

SparkRecord is a structured industrial record pipeline for Ignition. It receives three record lanes: Sparkplug B records (Cirrus Transmission Record objects, DataSet and Template metrics), JSON events on arbitrary MQTT topics through topic-to-stream templates, and SparkFlow events over NATS JetStream. Schema is discovered from the payload, versioned in a registry table, and migrated additively only, never destructively. Delivery is exactly once: source and receipt timestamps are stored separately, producer identity rides on every row, persistence is ordered per producer, deduplication is by content hash, and the ledger entry is written in the same transaction as the record. A value that fails type validation lands in a quarantine table with the reason recorded rather than being dropped. Every record's id is a SHA-256 hash over its canonical JSON, chained to the row before it, and a standalone verify CLI walks the chain and reports the first break.

2. What You Need

  • A SparkBridge Host gateway.
  • One of the supported destinations: PostgreSQL, SQL Server, TimescaleDB, Snowflake, or S3-compatible object storage.
  • For Sparkplug and MQTT JSON lanes: broker connectivity. For the SparkFlow lane: a NATS JetStream connection.

3. Install

Install the signed module through Config > Modules > Install or Upgrade a Module. Development use is free with no time limit; the module ships with freeModule=false and runs on Ignition's standard two-hour module trial until a verified license key is present.

Define sources and destinations in <Ignition data dir>/sparkrecord/config.json. If this file is absent or unreadable, the module starts with zero sources rather than refusing to start; a malformed entry inside the file is skipped and logged rather than aborting the whole file.

4. License

License key file at <data>/sparkbridge-license.key, re-checked every 30 seconds so installing, replacing, or removing the key takes effect with no restart. Without a verified key, SparkRecord runs on Ignition's standard two-hour module trial (Reset Trial on the gateway restarts the clock). A verified key naming SparkRecord overrides the trial entirely.

Early access. SparkRecord 0.1.0 shipped 2026-09-05 as an early access release; development use is free with no time limit.

5. Configure

Source and sink config file<Ignition data dir>/sparkrecord/config.json, containing a sources array. An unknown source type is logged and skipped rather than treated as a startup failure.
Status route/data/io.sparkrecord/status.json (module id path).
Supported source lanesSparkplug B (Cirrus Transmission Record, DataSet, Template metrics), MQTT JSON via topic-to-stream mapping, NATS JetStream (SparkFlow events).
Supported destinationsPostgreSQL, SQL Server, TimescaleDB, Snowflake, S3-compatible object storage. All destinations ship in the same license; there is no per-destination charge.

Schema is discovered from the payload and versioned in a registry table; migrations are additive and widening-only, never destructive. SQL is generated per destination dialect.

6. Operate

Records persist through an append-only writer, ordered per producer and deduplicated by content hash. A destination outage drains to disk and replays from the last committed offset with the original source timestamps intact, so an outage becomes a delay rather than a gap or a duplicate. A value that fails type validation is quarantined with its rejection reason recorded rather than silently dropped.

7. Verify

Use the standalone verify CLI to walk a stream's audit chain and confirm no break:

$ sparkrecord verify --table batch_events
row 41,882   record_id  a13f...9c02  prev_hash  8e4b...11ff  ok
row 41,883   record_id  c990...4a71  prev_hash  a13f...9c02  ok
row 41,884   record_id  7b21...0de3  prev_hash  c990...4a71  ok
chain verified: 41,884 rows, 0 breaks

Also confirm /data/io.sparkrecord/status.json reports the configured sources and sinks as running.
