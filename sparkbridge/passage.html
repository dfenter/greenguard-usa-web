OPC · Passage

The namespace, for everything that will never speak MQTT

Passage stands an OPC-UA server inside the gateway and serves the live Sparkplug namespace as an address space. Historians, SCADA packages and test rigs read it with the client they already own.

What it does

A translation, not a copy

Passage holds no store. It follows the live Sparkplug stream and shapes it into nodes as the estate births them.

Ages, not arrivals

A value arrives carrying its real age

OPC-UA has two timestamps and most bridges set them both to now. Passage sets SourceTimestamp to the instant the plant stamped the reading and ServerTimestamp to the instant it was handed over. In the capture above the gap is 2,685 milliseconds, because the value was genuinely that old. A client that trusts SourceTimestamp gets the truth.

Pushed

Subscriptions carry values, they do not poll

The stock Milo subscription model polls its data source on a timer. Passage implements the data-item hooks directly, so a value moves out to a subscribed client because it arrived on the bus, not because a timer came round. A tag that changes between polls is not lost.

Deaths

A dead node stays browsable and turns bad

When an edge node dies its nodes do not vanish. They stay in the address space and their value goes Bad_NotConnected, stamped at the instant of death. A client sees a fault it can alarm on rather than a hole in the tree.

The deliberate absence

There is no write path, on purpose

The fastest way to turn a read-only bridge into an incident is to add a convenience write.

How that is guaranteed

  • Every variable node is created READ_ONLY, so a write path cannot appear by oversight in a later change.
  • No NCMD is ever published. Passage subscribes and serves; it does not command.
  • The server ships as a scoped dependency on Ignition’s own OPC-UA module rather than bundling a second stack, which would double-initialise a shared event loop.

A gap we are not papering over

  • A passive consumer that starts after an edge node has published its BIRTH cannot see that node’s metrics until the next BIRTH.
  • Every fix for that costs a command path this product deliberately does not have.
  • The decision is open and written down in the repository ledger rather than quietly resolved. If it affects you, that shapes which way it goes.
Where it stands

Proven on a real estate, not yet on yours

Passage serves thirteen real metrics from a live gateway today. It has not run against a customer’s estate.

Done and measured

  • Thirteen live metrics browsed and read by an independent OPC-UA client.
  • Values and millisecond timestamps cross-checked against a separate MQTT probe: identical.
  • Source-versus-server delta of 2,685 ms observed on a handover, proving real age is preserved.
  • Death probe: node stays browsable, value goes Bad_NotConnected stamped at the death instant.
  • 22 offline tests, running live on an 8.1.54 gateway.

Owed before release

  • Security policies beyond anonymous.
  • The UNS JSON subtree and structured types.
  • A status and metrics surface.
  • A ten-thousand-item soak.
  • The BIRTH-gap decision, then licensing and a signed release.
