Certification summary

Sparkplug TCK Results

In plain terms: an independent test suite checked every rule the industry standard requires. SparkBridge passed all of it with zero failures. That means the data you receive follows the same rules as any other conformant system. It interoperates with your other plant equipment and software instead of needing custom fixes later.

One session, 2026-08-15, seed 240, produced with the officially ratified Eclipse Sparkplug TCK 3.0.0 binary against a complete live system: ten runs, 182 EDGE assertions passed and 52 HOST assertions passed, zero FAIL lines anywhere in the session log. Everything on this page is the TCK's own output, unedited, and reproducible with the harness that ships with the product, now from a single command.

Final Run Per Profile

PASS means every listed assertion executed and passed. One entry is complete-by-pair. The TCK's two SessionTermination Will assertions are protocol-conditional and provably cannot both execute in one run. The record holds one run per MQTT protocol version, and their union executes both and reads PASS. One assertion in the whole record returns MAYBE, and the reason is documented below.

The single MAYBE is tck-id-payloads-metric-datatype-not-req, a SHOULD-optional assertion about whether a datatype is included with metric definitions in NDATA, NCMD, DDATA and DCMD. It is the same class of result as the previous published record. Results are rolled up worst-result-wins, so a FAIL could never be cleared by a later run. There were none: the session log contains zero FAIL lines. The Host MessageOrdering profile, incomplete in the 2.2.2 record because that host required metric aliases in births, now runs every reordering assertion and passes.

Two profiles are not in the record and are stated here so the totals read correctly. Host MultipleBroker expects a host to hold simultaneous sessions on every listed server; the SparkBridge Host uses single-server-with-failover plus warm standby by design, so the profile was not run. The BROKER profile tests the broker itself; SparkBridge Provider defers to HiveMQ CE or embedded Moquette for that role and we make no broker-conformance claim of our own.
