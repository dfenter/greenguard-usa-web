Final Run Per Profile

PASS means every listed assertion executed and passed. Two entries are complete-by-pair: the TCK's two SessionTermination Will assertions are protocol-conditional and provably cannot both execute in one run, so the record holds one run per MQTT protocol version and their union executes both. One assertion in the whole record remains unexecuted, and the reason is documented, not hidden.

The unexecuted assertion (host reordering under a foreign reference edge) traces to a documented limitation: the host currently requires metric aliases in births, which Sparkplug makes optional. The fix touches the host's hottest lookup path and is scheduled with its own load testing rather than rushed into this record. Two interop defects the same scenario DID surface were fixed and shipped in 2.2.2 before this record was cut.
