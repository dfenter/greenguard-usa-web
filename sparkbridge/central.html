Publish once. Add consumers when you need them.

One server gives you one version of what your plants are doing. Adding another consumer, a historian, a warehouse, an analytics job, changes nothing at the sites: each site publishes once and Host fans it out. Host alone, no modules added, replaces the work of stitching together forty sites by hand. It collects what every Edge gateway reports, learns each site's tag structure the moment that site connects, and projects it as one live picture you can point any tool at.

Nobody builds that picture. When a site comes online it announces every device and every point it has, and Host creates the matching tags on the spot, in a tree that mirrors the plant. Add a device at a site and it appears at Host. Rename one and Host follows. There is no mapping spreadsheet and no import to repeat when a site changes.

Host knows the difference between a value that is current and one that is not. Every reading carries the time the equipment recorded it, not the time it arrived, so trends stay true through a dropped link and back. If a site loses its connection, Host marks that site's points bad instead of holding the last number, and when the site returns it asks for a fresh announcement so the two are in step again. A gap in the sequence from a site triggers the same check. Nothing quietly drifts.

It is the primary host on the network. Every Edge gateway watches for it, buffers while it is away and replays in order when it is back. Host holds one shared set of credentials and certificates for the estate, and it works with any conformant Sparkplug broker, including the one you already run. Its own status, throughput and per-site health are available over a plain REST interface for the monitoring you already have.

It runs on one server, at one license, whether you're watching five sites or five hundred. Its throughput has been measured on real hardware, and the figures are published on the technology page rather than claimed. The modules below are how you open that data, put numbers on it, secure it, check it, run it and keep it. Each one is installed only if you want it, and each one needs a SparkBridge Host gateway underneath it.

SparkCalc

One rate, one total, one efficiency number, calculated once.

Most plants compute the same figure in three places: a script on the historian, an expression in a dashboard and a spreadsheet in the office. They drift apart and nobody knows which one is right. SparkCalc computes it once, on Host, on the live data every site reports, and every system that needs the number reads the same one. Change the formula once and every consumer picks it up.

A result carries the quality of its inputs. If a site drops and one input goes stale, the result is marked uncertain instead of silently going wrong.

Example. A water utility has twelve lift stations reporting flow and run-time. SparkCalc keeps a rolling daily volume and a pump efficiency figure per station. The historian trends it, the morning report reads it and the alarm on low efficiency fires from it, all from one calculation.

What it does
InputsAny point Host holds, from any site
OutputsTags on Host, readable by every module and every tool
QualityStale or bad inputs mark the result uncertain
Change controlEdit the formula once; every consumer follows

SparkID

A read permission never quietly includes control.

Broker access rules are usually written by hand with wildcards, and a wildcard meant for reading often grants command rights nobody intended. SparkID generates the rules from a plain statement of intent: this site may publish its own data, this analyst may read everything, this operator may send commands to these devices. The generated rules do exactly that and nothing more.

Credentials rotate on a schedule without a human typing a topic pattern, and every identity is bound to one site so a credential from one site cannot speak for another.

Example. A contractor needs read access to one plant's data for a month. SparkID issues an identity scoped to that plant, read only, with an expiry. When the month ends the identity stops working and the audit trail shows exactly what it could see.

What it does
RulesGenerated from intent, deny by default

RotationScheduled, with no downtime for the site
EmitsBroker access rules for Provider and HiveMQ file RBAC

Passage

Every tool you already own reads your plant data directly.

Passage serves the live data Host holds over OPC-UA. Your historians, your SCADA, your analytics and test tools read it as a normal OPC-UA server, with the tag tree Host already built. Adding the next system becomes a subscription, not an integration project, and the plant is polled by nobody.

Example. A corporate historian sits in a data center and needs data from forty plants. Instead of forty OPC connections through forty firewalls, it connects once to Passage on Host and browses every plant from one address.

Reads fromEvery site Host hosts

Typical clientsHistorians, SCADA, MES, analytics, test rigs

Sentinel

A score for your plant data network, with the evidence and the fix.

Sentinel inspects the estate from Host: broker settings, certificates, identities, topic permissions, what each site can see and what each site can command. It scores what it finds, ranks the findings and gives you the evidence and the fix for each one. It observes and changes nothing on its own.

An optional compliance pack turns a Sentinel run into an auditor-ready binder for teams that have to produce evidence on a schedule.

Example. After a contractor commissions three new sites, a Sentinel run flags that one site's credential can publish to another site's topics and that a certificate expires in nine days. Both come with the exact rule change to make. The first time we ran it against our own systems it found four real problems.

What it does
ChecksBrokers, certificates, identities, permissions, site isolation
OutputRanked findings, each with evidence and a fix
Changes madeNone. Read only, by design
Add-onCompliance pack: the same findings as an audit binder

FleetOps

Every gateway you run, in one view.

FleetOps gives you one view of every gateway in the estate: module versions, drift from the configuration you intended, certificate expiry and backup status. Describe what a site is supposed to be once, as a template, and apply it to every site that matches. Sign a certificate rotation once and it runs fleet-wide, with each gateway reporting the new certificate back as evidence.

Example. A web certificate on one of forty gateways expires on a Saturday. FleetOps shows it in the expiring list a month out, alongside two sites running a module version nobody signed off. One signed action installs the new certificate, and the next inventory confirms it by fingerprint.

What it does
InventoryVersions, configuration, certificates, backups per gateway
DriftShows where a site differs from what you intended
ActionsSigned, allowlisted, applied fleet-wide, with evidence returned
DownloadFleet Ops 0.2.0, signed module

SparkVault

History is a consumer, not another integration project.

SparkVault subscribes to the backbone like any other consumer, so adding history changes nothing at the sites. It keeps your plant's history in an open database your existing tools read directly, filed under the time the equipment recorded each value rather than the time it arrived. When a site loses its link and replays its buffer hours later, the readings land where they belong and the trend shows the real curve. Any past day can be replayed on demand.

Example. A remote compressor station loses cellular for six hours overnight. In the morning the trend is complete, the monthly report built on it is right, and nobody exports a CSV from the site to patch the hole.

What it does
StoresEvery point Host holds, on the equipment's own timestamp
DatabaseOpen schema, readable by your existing tools
OutagesReplayed data backfills in place
ReplayAny past window, on demand

SparkInject

Your plant data in your warehouse, with no meter running.

SparkInject delivers production data from Host into your own data warehouse continuously. Every reading is tracked, so a restart or a dropped link cannot cause a gap or a duplicate. You own the warehouse account and the bill. We are never in the middle of it. Snowflake is the first connector family. Databricks and BigQuery follow.

Example. A data science team wants every plant's production counts in Snowflake by shift. SparkInject lands them as they happen, each row once, and the team builds on live tables instead of a nightly export.

optional module, pilot

GitOps / Enterprise Governance

Configuration as code for the whole estate.

Every gateway's configuration lives in a repository as signed bundles. A change is proposed, reviewed and applied from Host, and can be rolled back the same way. An audit trail records who changed what, when and why, across every site.

Example. A deadband change is proposed for all tank-level tags. A reviewer approves it, GitOps applies it to forty sites, and if it turns out wrong it is rolled back the same way, with the record showing every step.

What it does
Source of truthA repository of signed configuration bundles
WorkflowPropose, review, apply, roll back
AuditWho changed what, when and why, per site
StatusPilot

SparkFlow

Company-wide streaming, past the tag-count ceiling. SparkFlow runs on a SparkBridge Host gateway and carries its own license.

A plant with millions of points cannot put them all on tags at once, and eventually the estate hits the ceiling of how many it can carry live. SparkFlow moves the backbone onto a durable, replayable transport tier so the estate can stream company-wide, with the plant's Sparkplug data model kept intact end to end.

Example. Screens keep the tags operators watch. Every other point stays available from the stream, so a new dashboard or an analytics job subscribes to what it needs without adding a single tag on Host.

What it does
TransportDurable, replayable stream of every point Host decodes
TagsNone required behind a streamed point
DeliveryExactly once, with a last-value cache for new subscribers

Provider

The policy and routing layer for industrial data.

Provider carries plant data between sites and consumers while enforcing identity, permission and connection boundaries: per-site identities, deny-by-default topic permissions, MQTT 5 shared subscriptions for consumer scale-out. Edge and Host connect through it, and any conformant Sparkplug host can use it. Provider is priced separately at $1,995 per gateway. Broker shapes and internals are on the products page.
