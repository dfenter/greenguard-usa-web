## Repo Layout

The OPS portal is a single Next.js app, tenant-selected at runtime by
`BUSINESS_ID`:

```
app/                  → portal (Next.js, Pages Router)
  vercel.json         → framework: nextjs
  pages/              → Pages Router (NOT App Router)
  lib/                → service clients (stripe, hubspot, gcal, calcom, email)
  lib/businesses/greenguard/  → this tenant's config.js, catalog.js, business.yaml
  public/data/         → generated route plans (route_plan_YYYY-WW.json)
```

**Stack:** Next.js 15, React 18, JavaScript only (no TypeScript).
Customer/billing state lives in the CRM, the billing platform, and Google
Calendar. A Postgres database (`DATABASE_URL`) backs the bookkeeping ledger
and payroll.

## Booking & Billing Flow

```
Customer books → appointment lands on Google Calendar (admin@greenguard-usa.com)
  ↓
Tech does service visit → logged in Rounds (/admin/rounds)
  ↓
Admin generates invoice from Rounds → one-time invoice sent to customer
  ↓
Customer pays invoice → done

OR for new customers:
Admin builds quote (/admin/quote) → sends shareable link
  ↓
Customer approves quote → one-time checkout (first visit + one-time items)
  ↓
Customer picks an installation time via the booking embed at the end of the quote flow
```

**No subscriptions are created automatically.** Billing is invoice-based,
generated per service visit via Rounds.

## Services & Integration Map

### Billing — `app/lib/stripe.js`
- Invoices are the billing unit — created per service visit from Rounds
- Double-billing guard: booking UID stored in invoice metadata
- Webhook: `POST /api/webhooks/stripe` — handles `invoice.payment_succeeded`, `invoice.payment_failed`
- One-time SKUs only — see `lib/businesses/greenguard/catalog.js`

### CRM — `app/lib/hubspot.js`
- CRM: contacts created/updated when customers are added or an invoice is paid

### Payroll & timesheets — `app/lib/payroll.js` + `app/lib/payroll-store.js`
- **In-house payroll.** No third-party payroll provider; the portal computes gross, taxes and net.
- `lib/payroll.js` is PURE math (no I/O): FLSA weekly overtime, minimum-wage
  makeup, IRS Pub 15-T percentage-method withholding, FICA with wage-base
  caps, employer FUTA/state SUTA, non-taxable mileage up to the IRS rate.
- `lib/payroll-store.js` owns every SQL statement and the invariants: only
  *approved* entries are payable, finalizing claims them as *paid*,
  overlapping periods are refused, a void releases the hours and reverses
  the book entries in the original period.
- **Update the tax-year tables every January** (Pub 15-T, SS wage base, IRS
  mileage rate). See `## Policy` below (`compliance.taxTablesRefresh`).
- Authorization: `/admin/payroll` is OWNER-only; `/admin/timesheet` is any
  admin, scoped to the caller's own employee record.
- Finalized runs post to the books ledger.

**Time-card audit trail:** a DB trigger writes a revision row for every
insert/update/delete on `timesheet_entries`; the revisions table is
append-only (see `## Policy` — `compliance.timesheetAuditAppendOnly`).

**Env vars:** `DATABASE_URL`, `CALENDAR_TIMEZONE`

### Auth — `app/lib/auth.js`
- Magic link + JWT session cookie, 90-day, httpOnly, SameSite=Lax
- Multi-admin: `ADMIN_EMAILS` env var (comma-separated)
- Owner (`admin@greenguard-usa.com`) → lands on `/admin/home`
- Customers → `/dashboard`
- Prospects (no payment record) → `/prospect`

**Env vars:** `JWT_SECRET`, `ADMIN_EMAIL`, `ADMIN_EMAILS`, `NEXT_PUBLIC_APP_URL`

## Rules — Don't Break These

- **JavaScript only** — no TypeScript.
- **No subscription creation** — billing is invoice-based via Rounds.
- **Depot address**: `1519 Parkway, Austin, TX 78703` — used by the route optimizer.
- **Always deploy after portal changes** — run `./scripts/deploy.sh portal` after any edit to `app/`. Changes are not live until deployed.
- **Daily-ops pages read live calendar only** — never a route-plan cache. See `## Policy` (`scheduling.readLiveCalendarOnly`).
- **Never ask "should I notify"** — the channel rules in `## Policy` (`notifications`) decide.
