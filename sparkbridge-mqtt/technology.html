Technology

How it works

MQTT moves data around. Sparkplug adds what the data means, which site sent it, and whether it can still be trusted. Here is how that works.

spBv1.0/sparkbridge/NBIRTH/sparkplug

What Sparkplug Gives You

MQTT moves messages but says nothing about what is inside them. Sparkplug fills that gap, and gives every site the same four guarantees.

NBIRTH

Every site describes itself

On connection each site publishes a birth certificate: every point, its name, datatype, engineering units and current value. Consumers learn the model from the stream. There is no schema registry to fall out of date.

NDEATH

You know when a site goes offline

Sessions carry birth and death semantics enforced by the broker. When a site drops, every consumer knows within seconds and values are marked stale rather than left to look current.

NDATA

Only changes are sent

Only changes move. Steady-state load tracks what the process did, not how many tags exist. A structural property, not a tuning parameter that decays.

Template

Equipment arrives as whole objects

A pump, a loop, a skid crosses the wire as an object with named members, not a bag of loose points.

seq

You can tell if a message went missing

A rolling sequence number on every message means a consumer can prove it missed something and ask for a rebirth, rather than quietly carrying a hole.

STATE

Sites wait until the server is ready

Edges gate their births on the host's retained STATE, so a host restart does not produce an estate-wide stampede of uncoordinated births.

spBv1.0/sparkbridge/NDATA/lifecycle

One Connection, Start to Finish

All of the above happens in the life of a single connection. This is the order it happens in.

MessageWhat it establishes
STATEThe host announces itself, retained, so any edge connecting later knows the consumer is alive before it births.
NBIRTHThe edge publishes its whole model with seq=0 and a birth-death sequence number that identifies this session uniquely.
DBIRTHEach device below the node announces its own metrics, so a device can be retired later without disturbing the node.
NDATA / DDATAOnly changed values, alias-only on the wire, so the metric name was paid for once in the birth.
NCMD / DCMDThe host writes back. SparkBridge confirms the write when the edge reflects the value, not when the broker accepts the publish.
NDEATHRegistered as an MQTT Will at connect time, so the broker publishes it even when the edge cannot. Consumers stale the node's values.
RebirthA sequence gap makes the host ask for the model again, rate-limited per node so a lossy link cannot be amplified into a fleet-wide storm.

MQTT 5 and Beyond

The group that maintains Sparkplug has said where the next version is heading. Everything in the right-hand column already ships and can be switched on today.

Anticipated directionSparkBridge today
MQTT 5 as the baseline transportFull v5 client mode behind a flag: will delay, message expiry, receive maximum, topic aliases, noLocal, reason-code surfacing. No regression against 3.1.1; mixed v3 and v5 fleets interoperate through the broker.
Shared subscriptions for host scale-outMeasured at about 20x delivered ingest with four consumers. The largest single advantage over a 3.1.1-only implementation, because it removes the single-wildcard-subscriber ceiling.
Session and message expiry, reason codesPer-publish expiry for live data, with births, deaths and STATE never expiring. A denied publish surfaces as a diagnosable reason code rather than silence.
Topic aliasesLong spBv1.0/… topics compress to a two-byte alias on repeat.
Sparkplug Aware brokersConsumed today: a late-joining host primes from the broker's retained certificates instead of triggering an estate-wide rebirth.
Deeper historical replayShipped ahead of the standard: capture timestamps and the historical flag survive replay, and backfill is counted separately from live data.
spBv1.0/sparkbridge/NBIRTH/uns

The Unified Namespace, Explained

One up-to-date picture of the plant that every system reads from. You get it as a result of publishing properly, with no second project to fund.

What comes as standard

It builds itself

Because each site describes itself when it connects, the picture fills in as sites come online. Anything new (a dashboard, a historian, an analytics tool) subscribes and finds what is there, rather than needing to be configured tag by tag.

What SparkBridge adds

Plain JSON as well as Sparkplug

The Edge can also send the same values as plain JSON on a readable path, for tools that cannot read the Sparkplug format. Sparkplug for the systems that need types and connection state; JSON for the ones that just need a simple feed.

The Standard Is Only the Start

Conformance is table stakes. What decides an estate's operating cost is everything the standard leaves open: buffering, scale-out, identity scoping, hot reload, and observability.
