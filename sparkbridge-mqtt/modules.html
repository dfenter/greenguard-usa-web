Modules

Edge, Host and Provider

Three modules for Ignition. Install the ones a site needs, and each works with any conformant Sparkplug software on the other side.

Edge Node · publisher

Edge

Publishes Ignition tag data as Sparkplug and keeps publishing into a disk buffer when the link drops.

Host Application · consumer

Host

Subscribes to the namespace, learns each node's model from its birth certificate, projects it into a tag provider.

Broker · infrastructure

Provider

Embedded broker for one node, or control of a HiveMQ CE companion for MQTT 5 and shared subscriptions.

spBv1.0/sparkbridge/NBIRTH/edge

Edge

A site publishes once and every system that wants the data subscribes. The Edge is built for what comes after that: link outages, model changes, and tag counts in six figures.

CapabilityDetail
250,000 tag budgetScalar leaves and unfolded UDT members count against one budget. A UDT is admitted whole or skipped whole, never half. Subscriptions install in 10,000-path chunks so a large site does not stall the tag system.
Store and forwardDisk-backed, 50 MB default, batched fsync measured at about 2,697 messages/s durable; per-record fsync available. Buffered values keep their capture timestamps and carry is_historical, so a historian backfills the real curve. Measured lossless: 400,000 of 400,000 replayed in 20.33 s.
Device modelingFolders at a configured depth become Sparkplug Devices with their own DBIRTH and DDEATH, hot-reloaded on rescan without disturbing the session. Write-back is deny-by-default: a DCMD is rejected unless a device/metric pattern opts it in.
Sparse TemplatesDefinitions deduplicated ahead of instances; BIRTH carries the full instance, NDATA only the members that moved, explicit null transitions retained.
Metadata foldingUnits, description and ranges ride the birth certificate as a PropertySet, so roughly a third of points leave the steady-state stream while the model becomes more self-describing, not less.
Up to 8 edge nodesEach with its own transport, subscriptions, buffer and birth sequence state, so one site's problem is not another's.
Primary host lifecycleBirths gated on the host's STATE; a valid host-offline terminates the session and walks to the next server. Verified by the TCK PrimaryHostTest.
spBv1.0/sparkbridge/NBIRTH/host

Host

The Host is where fleet scale is won or lost, so this is where the engineering went.

CapabilityDetail
Self-learning tagsThe model arrives in the birth certificate; tags appear as sites come online. Templates expand into member tags and folded metadata projects onto standard engineering properties.
500,000 wire metricsResident in under 4 GiB, with per-metric cost measured flat from 250,000 through 1,000,000, with no cliff waiting in production.
Sharded ingestPer-node order preserved while sites decode in parallel, bounded queues, and a control-divert path so a death or a command never queues behind a deep backlog of data.
Shared-subscription scale-outMQTT 5 consumers share one broker stream: about 20x delivered ingest with four consumers against one.
Simultaneous multi-serverA session on every configured server, retained STATE per server stamped with that server's connect time, and commands routed only to where the edge was last heard.
Confirmed write-backA command reports success when the edge reflects the commanded value, not when the broker accepts the publish.
ObservabilityLive dashboard, node inventory, Prometheus metrics that separate wire metrics from projected tags and replay volume from live data, and latency histograms.
spBv1.0/sparkbridge/NBIRTH/provider

Provider

Sparkplug leaves security to the implementation, so the broker is where your security posture is set.

CapabilityDetail
Two broker shapesEmbedded Moquette on loopback for a single node, nothing to install; or a HiveMQ CE companion for MQTT 5, shared subscriptions and Sparkplug Aware certificates. Neither is licensed by connected-client count.
Per-site identity scopingAn edge credential is bound to one group and node; an unlisted edge user is denied. A scoped credential must present its own deterministic client ID, so one site cannot evict another's session.
No command injectionEdge identities cannot publish NCMD, DCMD or STATE at all. Structurally unavailable, proven live against the deployed ACL.
Application-topic ACLUNS, file-transfer and bridge topics are authorized per identity by prefix and denied by default, so one site's credential cannot forge another site's data.
TLS and mTLSHostname verification mandatory; disabling it requires an explicit development-only flag with no production use.
Read-only posture pageThe effective security settings are shown in the gateway UI and cannot be widened from the web.
